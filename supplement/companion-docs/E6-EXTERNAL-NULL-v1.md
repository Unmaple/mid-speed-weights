## 0. 这个实验在问什么

Δ 是**条件于历史 H** 的写入。那么把 Δ 打开、但**不放 H**（纯文本输入），模型应当基本不变——因为 H 之外的一切都与这次写入无关。

所以：

> **在 H 之外的文本上，`base+Δ` 应当与 `base` 不可区分。** 测不可区分性，用量化界的标准仪器（WikiText-2 上的逐位置 KL + top-1 一致率），而不是再生成一批合成题。

用外部语料而不是自造题的理由（写进报告时要说明）：

1. 自造的"无关题"与 H 出自同一生成器，共享句法与命名，**不构成"之外"**；
2. 外部语料有**可比的单位**——同一指标上，4-bit 量化大约是 KLD 0.14 / top-1 一致率 89 %，我们的数字可以直接放到那把尺子上；
3. 它是稠密的（每个位置都算），自造题是稀疏的（每题一个答案），后者会藏住损伤。

**这个实验不依赖 H、不依赖教师、不依赖探针集，只依赖 base 权重 + 一个 Δ checkpoint。** 会话侧的机器全坏也能跑。

## 1. 假设与预注册判据

### H1 全局扰动小（主要假设）

`KL(base ‖ base+Δ)` 在 WikiText-2 上显著小于一个事先声明的等效界。

- **等效界 δ = 0.010 nats/token**（借用量化讨论里的量级，**是选定的界，不是测量值**）。
- **判据：TOST。** 取 90 % 置信区间（两个单侧检验各 α=0.05），要求区间**上界 < δ** 才算"等效"。
- **不接受的写法**："没测出显著差异" ⇒ 必须写 **inconclusive**。这是本项目的既有纪律，不破例。

### H2 局部性（进攻性主张）

Δ 的全局扰动远小于一次同模型上的 4-bit 量化，而它在目标分布上的效果是 28.47 % 的 KL 降幅。

- **判据：`KLD(Δ) / KLD(Q4_same_model) < 0.10`**（同模型、同语料、同口径的比值，避免跨模型混淆）。
- 成立则可写：**"Δ 是局部的——目标分布上改变 28 %，全局文本上的扰动不到一次 Q4 量化的十分之一。"**
- 不成立（比值 ≥ 0.10）则只报数字，不写"局部性"。

### H3 不损伤语言建模能力

`PPL_Δ / PPL_base − 1` 的 90 % CI 上界 < **1 %**。

## 2. 数据

### 2.1 语料

**WikiText-2 raw test set。**

- 获取：HuggingFace `Salesforce/wikitext`，配置 `wikitext-2-raw-v1`，split `test`。
- 拼接：把每行的 `text` 字段按数据顺序用**单个换行符 `\n`** 连接，**不做 detokenize、不做任何清洗、不丢空行**。
- 把拼接后的整段文本写入一个文件并记录其 **sha256**，后续一切从该文件出发。

> 说明：llama.cpp 的 `prepare-wikitext-2.sh` 会额外做 detokenize，所以我们的 token 序列与它不会逐字相同。**这不影响本实验的自洽性**（base 与 Δ 看的是同一份 token），只影响与外部数字的"近似可比"，报告里要注明。

### 2.2 分词

- 用 base 模型自己的 tokenizer，`add_special_tokens=False`，一次性把全文编码为**一个** token 序列。
- 记录 **token 总数**。
- **sanity gate**：base 模型在本切片上的 PPL 应当与该模型公开报告的量级一致（同量级即可，不要追求相等）。若偏差超过 2 倍，**停止**，先查 tokenizer/拼接是否用错。

### 2.3 切窗

- 连续切 **512 token** 的窗，**不重叠**，最后不足 512 的尾巴丢弃。
- 取**前 N 个窗**，`N = 50`（基准）或 `N = 200`（扩样，见 §5）。
- **计分位置：每个窗内下标 256…510，共 255 个位置。**
  - 原因：位置 `t` 的 logits 预测 `t+1`，而最后一个位置的预测目标落在窗外，故被丢弃。
  - 校验：50 × 255 = **12,750**。这个数与外部参考表一致，算对不上说明切窗错了。

## 3. 模型与臂

| 臂 | 内容 | 作用 |
|---|---|---|
| `base` | Δ = 0（本项目里 `B0 = 0` ⇒ **逐位恒等**） | 参考 |
| `delta` | 已训练的 Δ checkpoint | 测量对象 |
| `rand` | 同秩（64）、同层、同参数量的随机 ΔW，Frobenius 范数与 `delta` 匹配 | null-of-null |
| `q4` | 同一 base 权重的 4-bit 量化（如 `bitsandbytes` nf4，bfloat16 计算） | H2 的比值分母 |

**checkpoint**：优先用 `.local-8b/m43_batch.pt`；不存在则用 `.local-8b/m43_batchtrain.py` 按同一配置重训并记录种子。**加载后打印 Δ 的键名、形状、dtype、目标层、rank、Frobenius 范数并写入报告**——不要假设 checkpoint 里的结构，先看再加载。

**随机臂的范数匹配**：预先声明匹配 **Frobenius 范数**（不匹配谱范数），并报出实际值。事后换范数类型等于事后改判据。

## 4. 测量口径

对每个计分位置 `t`（目标 token `w = x_{t+1}`）：

```
p_base, p_delta ∈ R^V            # softmax 在 float32 里算，别用 bf16
KL_t   = Σ_v p_base(v) · ( log p_base(v) − log p_delta(v) )     # 方向：KL(base ‖ delta)
top1_t = 1[ argmax p_base == argmax p_delta ]
dp_t   = p_delta(w) − p_base(w)                                  # 正 = delta 更准
```

按位置聚合，并**按窗口（chunk）做配对 bootstrap**（10,000 次，seed 固定）取置信区间——同一窗内的位置相关，不能当独立样本。

报告字段：

| 字段 | 定义 |
|---|---|
| `kld_mean` / `kld_se` | 全部计分位置的均值与 bootstrap SE |
| `kld_p99` / `kld_p999` | 分位（损伤集中在少数位置，均值会抹平） |
| `kld_ci90_lo` / `kld_ci90_hi` | 90 % CI（TOST 用） |
| `top1_agree` / `top1_se` | argmax 一致率与二项 SE |
| `dp_mean` / `dp_rms` | 正确 token 概率变化 |
| `ppl_base` / `ppl_delta` / `ppl_ratio` | 两个模型的 PPL 及其比 |
| `n_chunks` / `n_positions` / `vocab` | 规模 |
| `corpus_sha256` / `token_total` / `delta_sha256` / `seed` | 可复算凭据 |

**参考 logits 必须缓存到磁盘一次**，`delta` 与 `rand` 臂复用同一份，杜绝参考漂移。

---

## 5. 功效与扩样

先跑 `N = 50`。若 `kld_ci90_hi − kld_ci90_lo > 0.005`，**扩到 `N = 200`**（取同一序列的**前缀**，即前 200 个窗，不要换语料）。扩样后重报全部字段，并注明扩样原因。

## 6. 决断表

| 观测 | 结论 |
|---|---|
| `kld_ci90_hi < 0.010` 且 `top1_agree ≥ 99 %` | H1 成立：全局扰动可忽略 |
| `kld_ci90_hi ≥ 0.010` | H1 **不成立或 inconclusive**（看 `kld_mean` 是否也 ≥ δ）。**不得写"等效"** |
| `kld(Δ) / kld(q4) < 0.10` | H2 成立：可写"局部性" |
| `ppl_ratio` 的 90 % CI 上界 < 1.01 | H3 成立：不损伤语言建模 |
| `rand` 臂的 `kld` ≥ `delta` 臂 | 正常（随机扰动应不更优） |
| `rand` 臂的 `kld` **明显小于** `delta` 臂 | **异常**，先查范数匹配与加载，不要先下结论 |

## 7. 禁止事项

1. **不要用合成题当"无关"对照。** 与 H 同源，不构成外部。
2. **不要把本实验的绝对 KLD 与跨模型的外部表直接比。** 外部参考（4-bit，27B 级 MoE）是 **KLD ≈ 0.14 / top-1 ≈ 89 %**，只作量级参照；模型、语料切法、参考实现都不同。
3. **不要用"没显著差异"代替等效。** 必须 TOST + 预先声明的 δ。
4. **不要用 WikiText-2 的 KLD 去选 rank / 层 / 学习率。** 否则这个"无关对照"变成了调参目标，它的意义就没了。本实验的参数必须来自其他实验，跑完再测。
5. **不要用 batch > 1 做计分前向。** 批大小会改变 GPU 数值累积顺序，足以污染这一量级的差异。计分时 batch 固定为 1；若必须批处理，先做一次 batch=1 与 batch=8 的自比，确认 KLD < 1e-5 再放行，并把该自比写进报告。
6. **不要采样解码。** 全部 teacher-forced。
7. **不要只报均值。** 必须报 p99 / p99.9（损伤在尾部）。

## 附：数字自检

```
50 × 255        = 12,750      # 基准位置的数目，对不上就是切窗错
12,750 / 25,600 = 49.8%       # 计分位置占比（每窗后半段），应略低于 50%
200 × 255       = 51,000
```

外部量级参照（**不同模型、不同切法，仅作尺子**）：

| 参考 | KLD | top-1 一致率 |
|---|---:|---:|
| 4-bit（同族 MoE，官方 Q8 参考） | ≈ 0.138 | ≈ 88.8 % |
| 3-bit | ≈ 0.238 | ≈ 85.2 % |

我们的预测：`KLD(Δ)` **远小于 0.138**（Δ 只动 4 个 `down_proj`、秩 64；量化动全部权重到 4 bit）。若测出来反而接近或超过这一档，说明写入的全局代价被严重低估，这本身就是重要发现，要如实报。
