# 设计备忘：把 H 换成 agent 轨迹，把重放拆成 NREM / REM

日期 2026-10-27。**本文只是设计与可判性分析，没有跑任何实验。**
依据的既有读数见 `results/README.md`。

---

## 0. 提议（先把话精确化）

现在的 H 是一份**账本**（55 行登记记录），Δ 学到的是"回答问题的分布"。提议把 H 换成**一次多轮 agent 工作轨迹**：

```
H = 默认 agents + system prompt + A + R
    A = 外部输入（用户轮、工具返回、报错）
    R = agent 自己的输出轮（含工具调用、计划、结论）
```

两条主张：

1. **学习对象变了**：Δ 要拟合的不是"事实"，而是 **agent 在 A 之下的行为倾向**。R 本身是 A 的条件分布，
   所以"拟合 R" = "拟合条件策略"，这比"拟合账本"更接近"经历"。
2. **重放要分成两种**（用户的 NREM/REM 类比）：
   - **NREM（经历回放）**：agent 在 A 之下实际做了什么 → 位置级、忠实。
   - **REM（日有所思夜有所梦）**：H Teacher 自己**关注**什么 → 由注意力/不确定性生成的 probe。

## 1. 用户点名的两个问题，我的分析

### 1.1 要不要把工具输出 / 用户输入当拟合目标？——**建议不**（作条件，不作目标）

支持的三个理由：

1. **杠杆不对称。** agent 能控制的是 R，不是 A。在 A 的位置上做 KL，等于让 Δ 去学一个它无法影响的过程。
2. **部署风险（最实质的一条）。** Δ 是在 agent **行动中**装着的。若它被训练去预测工具输出，它就有可能在工具真正返回
   之前把结果写出来——这不是"记忆偏差"，而是**伪造观测**。这是我认为必须回避的第一顺位风险。
3. **定义一致性。** 本项目对"记住"的定义一直是"复现教师"，而"教师对用户的下一句话"分布在 H 之外几乎不可学
   （用户意图是外生的）。把它当目标会把 Δ 变成用户模型，而不是会话状态。

反方（要当目标）的论点，我认为**不足以推翻**，但值得记：

- 如果目标是"压缩后仍能像原来那样把对话进行下去"，模型确实需要能预判"下一条输入大概是什么"，否则不知道何时收尾。
- 但这个能力**由基础模型提供就够了**：A 在上下文里，Δ 只需要条件于它。所以它是"条件"，不是"目标"。

**可判做法**：同一份 H，两臂——`RD_Ronly`（只在 R 位置监督）与 `RD_all`（全部位置）。读数见 §4。
我的先验：`RD_all` 的外部扰动更大、更可能出现工具幻觉，而在 held-out 行为上不会更好。**这是先验，不是结论。**

### 1.2 A 要不要回放？——**在 R-only 方案里这个问题自动消解**

R-only 下，A 从不作为目标出现，只作为上下文。所以"回放 A"就只剩一个独立问题：**要不要额外为"用户/环境模型"再训练一个东西**。
我的建议是**不要混进同一个 Δ**：混进去之后，"这个 Δ 代表什么"就没有单一解释了。若确实要做，应作为**第二个载体**单独评估。

用户自己也留了口子（"具体 A 要不要回放，那另说"），我同意先不定。

## 2. NREM / REM 怎么落地

**先把 REM 的定义写对**（我第一版写错了，记在这里）：REM 不是"想办法提取注意力权重"，
而是——**让 teacher 自己挑 probe**。它挑出来的东西就是它关注的地方，按这些地方重放，
就是"日有所思夜有所梦"。

这个操作在本项目里已经验证过可行，不是新发明：

- `m44_teacher_probe.py`：让教师自己列出"这段历史里有哪些实体、每个实体有哪些字段"，
  结果 **55/55 实体（precision 1.00）**、**4/4 字段（含从未被问过的 `region`）**，
  共 220 个格子，对 48 个留出格子 **100% 覆盖**，40 道题全部被覆盖到。
- 代价是**过度列举**（220 vs 真实 108）：它不知道将来会问什么，只能把"值得记的"都列出来。

所以 REM 的实现路径是**生成**，不是**探测**：

```
teacher = base + H in context
prompt  = "这段历史里，哪些东西是你认为必须记住的？逐条列出。"
→ teacher 列出的条目 → 转成 probe（每格一条问句）→ 作为 REM 的重放集
```

**这同时修掉 `rd_fits_h.md` 暴露的那个问题**：那里 RD 在外部文本上离 H 有 3.06，原因是
probe 只覆盖了我挑的 186 个答案位。如果 probe 由 teacher 自己挑，覆盖面就跟着**教师的关注点**走，
而不是跟着我的猜测走。

### 2.1 仍然要做对照，但对照不是"REM 的定义"

三种"挑法"要放在一起比，因为**它们选出的集合不一样，而哪一个才对应"梦"是个经验问题**：

| 挑法 | 谁在挑 | 预期 |
|---|---|---|
| **(T) teacher** | teacher 自己列"必须记住的" | 用户主张的 REM |
| **(H) human** | 我（现有 186 条探针） | 现状基线，已知偏窄 |
| **(G) gap** | 无 Δ 学生在各位置 KL 最大的地方 | "复习错题"，不是梦 |
| **(N) NREM** | 直接取 R 位置（agent 实际输出） | 经历回放，非 probe |

**这一步不需要训练**：在同一份 H 上把 (T)(H)(G) 三个集合都算出来，比较重叠度与类别分布。
若 (T) 与 (G) 高度不重叠，说明"教师关注"与"学生缺"是两件事——那 REM 选哪个才有内容；
若高度重叠，争议自然消失。

（顺序上，它排在 §4.0.1 信息值筛选**之后**：先确认这个任务族里有承重事实，再讨论"谁来挑 probe"。）

### 2.2 判据：RD 离 H 多远（**撤回**上一版的"教师没列出"口径）

上一版我写过"必须在 teacher 没列出的条目上赢"，这是错的，撤回。理由：

- **目标就是 RD→H。** H 是固定的、不由 teacher 挑选的。判据因此只有一条：
  **KL(H‖RD)，在训练没碰过的位置上量。**
- **teacher 挑 probe 不构成循环。** 挑 probe 是**训练集怎么选**；测试侧是 H 本身。两者不同源。
  只有当"训练集 = 测试集"时才是同义反复，而这里天然分离。
- **真正的风险是覆盖面，不是循环。** 若 teacher 只挑它关注的位置，RD 会在那些位置像 H、别处不像。
  这不需要额外机制去"修"，它就是留出位置上的 KL 本身会显示出来的东西。

这与 m59b 是同一件事：那次 `KL(H‖RD)` 在外部文本上是 **3.06**（基准 `KL(H‖R)` = **0.2034**），
原因是 probe 只覆盖我挑的 186 个答案位。**m59b 的 3.06 / 0.2034 就是这次比较的现成基线**，
同口径、同一份 H，可直接对照。

（thres 提示：因为判据是"接近 H"，所以 `RD` 的 KL 只要**低于 0.2034** 才算开始起作用——
即"比什么都不做更接近 H"。这句话是判据，不是结论。）

## 4. 最小可判实验

### 4.0 顺序：先把任务设计出来，再采集上下文

**这是一条硬约束，不是建议。** 在跑 agent 之前必须先回答三件事，否则采回来的 H 只是一段长文本：

1. **任务够不够长、够不够痛？** ≥10 轮、含 **≥2 次真实失败与修正**。一次就成功的轨迹里 R 的信息量太低。
2. **里面有没有"承重事实"？** 知道它 → 行为改变；不知道 → 行为错。这是"究竟有什么内容是他知道新信息之后
   就会有行为上的改变"的直接操作化。
3. **这些事实是不是必须通过失败才能拿到？** 若 system prompt 一句话就能给，测的是指令遵循，不是经历。

#### 4.0.1 信息值筛选（先做，不训练，几分钟）

对每条候选事实 `f`，用**基座**跑三个条件，比较**下一步动作**（tool call 的 name+args，不是文本）：

| 条件 | 上下文 |
|---|---|
| `∅` | 任务描述，不含 `f` |
| `+f` | 任务描述里补一句 `f` |
| `T-f` | teacher（base+H），其中 `f` 是通过失败获得的 |

判读（三种结果都有信息，别只留"通过"的）：

- `∅` 与 `+f` **动作相同** → `f` 不承重（基座本来就猜对了，或根本不在意）→ **不进 H**。
  这类事实放进去也只是背景噪声，而 E6 已经说明背景噪声要付扰动代价。
- `∅` 与 `+f` **不同且 `+f` 正确** → `f` 承重，可用。这就是"知道就会变"。
- `T-f` 与 `+f` 不同 → teacher 在长上下文里没把 `f` 用起来（可能被淹没了）。**记下来**：
  这本身就是"长 H 里的事实衰减"，是独立现象，不丢。

产出是一张**只剩承重事实的任务清单**。没通过筛选的任务不进实验。

#### 4.0.2 任务规格（硬性）

| 要求 | 判据 |
|---|---|
| 长度 | ≥10 轮，≥2 次失败-修正 |
| 承重事实 | ≥2 条，每条都过 4.0.1 |
| 可判定 | 结束状态由**环境**检查（退出码/文件/端口响应），不靠人看 |
| held-out | 同结构换表面的第二实例（不同路径、不同字段名、不同报错文本） |
| 可重跑 | 固定种子、固定启动方式 |

#### 4.0.3 候选任务族：本机 PowerShell/GPU 三连坑

用户举的"小迷你 agent 在本机上死磕 PowerShell"，在本次会话里**真实发生过**，所以坑、报错文本、
修法都是现成的：

| 承重事实 | 不知道时的行为 | 知道后的行为 | 自动判定 | 动作级初判（m63） |
|---|---|---|---|---|
| `F1` python 必须是 `.local-8b\venv\Scripts\python.exe`（系统 python 无 torch） | `python x.py` → `ModuleNotFoundError` | `.\venv\Scripts\python.exe x.py` | 退出码 + stderr 关键字 | **翻**（`+f` 与 `T-f` 都翻） |
| `F2` 含 CJK/引号的代码不要内联进 `pwsh -Command` | `SyntaxError: unterminated string literal` / `'(' was never closed` | 写成 `.py` 再执行 | 是否产出 `.py` 且无 SyntaxError | **`+f` 翻，`T-f` 不翻**（照样内联） |
| `F3` 32 层里只有 8 层是 full_attention，24 层是 GDN | 对 32 层取 attention → 24 个 `None` | 先读 `layer_types` 只取 8 层 | 返回矩阵数 = 8 | **`+f` 翻方向，`T-f` 退回全 32 层** |
| `F4` 参考侧必须先 `no_delta()` 再 `use(state)` | KL ≡ 0、top1 = 1.000（假成功） | 先算参考再装 Δ | 输出是否退化 | **`+f` 翻方向（`use_delta=False`），`T-f` 无关** |
| ~~`F5` VRAM 上限 22528 MB~~ | OOM → 重跑 | `pack_on_cpu=True` + fp16 | 是否 OOM / 峰值显存 | **删掉**：偏好没动，经历记录 0.00 |

`F4` 特别值得放进任务：它**不报错**，只给出一个"太漂亮"的数字。这类事实区分"记住经历"与"记住事实"——
它是一条**关于怎么测量**的经验，不是一个参数值。

任务：让 agent 在本机跑通一个三步小实验（写脚本 → 上 GPU → 出数）。`F1/F2` 在真实执行中依次触发
（解释器与内联写法），`F3` 在"看历史里哪些位置被关注"那一步触发，`F4` 由一个"看起来成功了"的中间结果触发。

#### 4.0.6 4.0.1 已经跑过两遍（m62/m62b 偏好题，m63 动作题）

详见 `results/info_value_screen.md`。四条结论直接影响上面的任务设计：

1. **偏好题和动作题会分歧，且方向不固定。** 偏好题说 F2/F4"本来就会"；动作题（问"下一条命令是什么"）
   说 `∅` 时它们**做错了**。所以判承重性必须看**动作**，不看偏好。
2. **规则 4/4 改变动作，失败记录只有 1/4。** 把两句 `SyntaxError` 原样给它，下一次照样内联；
   一句"必须先写成 .py"就改了。F3 更差：看过"24 层是 None"，它退回"全部 32 层"。
   **把经历原样留在上下文里，可能什么也教不会。**
3. **模型会为 sunk API 编名字。** F3/F4 方向全对但函数名是假的（`get_model_state()`、`use_delta=False`）。
   这类事实的读数只能是"方向"，字面复现要靠训练——这正是 Δ 该做的事。
4. **F5 删掉**：偏好没动（`Δ(T-f)=0.00`），动作没重筛，两条都不满足。

因此 agentic 链的价值不在"把经历存下来"，而在**从经历里抽出规则**。这条推论把优先级推到了
`DESIGN-SKILL-DISTILL-v1.md`：skill 文档本身就是规则，且它的门槛测试（m64）已经通过——
给 skill 时模型连"示例里从未出现过"的回滚规则都照做。**建议先跑 skill 蒸馏，再回来做 agentic 链。**

四个坑按顺序自然触发，不需要人为埋设——本次会话里它们真的依次发生过。

| 14 | R | 正常数 + 结论 | — | — | — |

设计要点：

- **`F2` 出现两次**（轮 3、5）才够格确立一条事实。单次报错更像偶发，模型有理由再试一次内联。
  这正好对应"≥2 次失败-修正"。
- **轮 11 是静默失败**，只有用户轮（轮 12）能揭穿。它是整条链上唯一**不能由环境报错自动发现**的坑，
  因此也是最像"经历"的一环：要记住的不是报错文本，而是"这个数字太漂亮了，得查"。
- **轮 9 的报错是软失败**（不抛异常，只是给了 24 个 `None`）。它比硬报错更接近"静默失败"，
  因为不看结果就不会发现。
- **held-out 实例**：同结构换表面——换脚本（跑 `m58` 的 tails 而不是 `m50`）、换 venv 相对路径（`venv312\`）。
  承重事实不变，`F2` 的报错文本与 `F1` 的模块名不变（它们是真机的真报错）。
- **2×2 的 `H_A`/`H_B` 就从这条链上切**：`H_B` = 把轮 8 的解释器换成分数路径的 venv（`venv312\`），其余全同。
  于是 `P_A`/`P_B` = "下一步该用哪个解释器"。

#### 4.0.5 账本为什么成功，以及 agentic 版本难在哪

账本 H 的 55 条事实都是**不可猜**的（实体、地址、字段值任意），所以"有事实 / 没事实"必然给出不同答案——
信息值筛选在那种构造下是**自动满足**的，这就是为什么 m50/m59b 的 KL 读数一直有东西可测。

agentic 版本要难得多：这里的承重事实必须是**可猜、但先验猜错**的东西。实测（§4.0.6）正好分开两类：
`F1`（用哪个解释器）与 `F3`（哪些层有 attention）**先验是错的**，事实一到就翻；而 `F2`（先写文件）与
`F4`（先算参考）**先验已经对了**，事实只让它更自信。所以 agentic H 的成功条件不是"信息量足够大"，
而是"**先验足够错**"——4.0.1 筛掉的正是那一类看起来像坑、其实模型早就会的事实。

这也解释了账本为什么没这个问题：账本的事实是任意字符串，不存在"先验已经对了"的可能。

**臂（4 个）**：

| 臂 | 监督位置 |
|---|---|
| `RD_Ronly` | 仅 R（agent 输出）← 这就是 NREM |
| `RD_all` | 全部位置（含 A）← 检验 §1.1 的"不拟合外生输入" |
| `RD_human` | R + 我手写的探针（现状基线） |
| `RD_rem` | R + **teacher 自选**的 probe |

（若 §2.1 的离线比较发现 (G) 与 (T) 明显不同，再加第五臂 `RD_gap`。）

**读数（五个）**：

1. **主判据：`KL(H‖RD)`，在训练没碰过的位置上。** 这是 §2.2 定的唯一目标口径。
   现成基线：**0.2034**（`KL(H‖R)`）；m59b 里 RD 最好的一次是 0.2693、最差 3.06。
2. **2×2 交叉矩阵（行为读数，不靠 KL）。** 造两份只差一条承重事实的 H（`H_A`/`H_B`，
   例如"8443 被占用"/"8443 空闲"），训 `Δ_A`/`Δ_B`，配两条留出 probe `P_A`/`P_B`。
   期望：**对角对**（RD_A 在 P_A 上给 A 的答案），**非对角要落在"另一个 H 的答案"上，而不是随机**。

   |  | `P_A` | `P_B` |
   |---|---|---|
   | `RD_A` | A 的答案 ✓ | B 的答案（**这才说明 Δ 带的是会话信息**） |
   | `RD_B` | A 的答案 | B 的答案 ✓ |

   非对角若退化成均匀/乱码，说明 Δ 只是噪声，不是"记住了另一件事"——这两种情况必须分开。
3. **工具幻觉率**：工具返回前是否已写出结果。
4. **外部扰动**：E6 口径 `KL(R‖RD)`（代价）。
5. **端到端成功率**：装回 Δ 跑任务，环境判定通过与否。

**预先写死的判据**：

- (1) `RD` 的 `KL(H‖RD)` 在留出位置上 **< 0.2034**，且 bootstrap CI 上界也 < 0.2034。否则"RD→H"不成立。
- (1') 若所有 checkpoint 都 ≥ 0.2034，**按 m59b 的既有结论处理，不调参救**：报告"Δ 拟合的是答案位分布，
  不是 H 对模型的作用"，并把它作为 agentic 版本的前置障碍。
- (2) 对角正确率 ≥ 0.8，且非对角"另一个 H 的答案"占比 ≥ 0.6。只满足前一半不算。
- (3) `RD_Ronly` 的幻觉率必须显著低于 `RD_all`，否则 §1.1 的设计理由不成立。
- (4) 任何一臂扰动 > 0.5（E6：3e-4 是 0.063、6e-4 是 1.58），标"代价过高"，即使 (1) 更好也不改判。

**为什么 (2) 不能省**：m59b 已经显示 KL 可以"变大"（0.2034 → 3.06），但没说明 RD 偏离的是**方向**还是**噪声**。
(2) 是唯一能区分这两者的读数——它要求 Δ 在偏离 R 的同时，偏离到**另一份具体的 H** 上去。

## 5. 风险 / 我不确定的地方

1. **单一任务 → 结论可能只对这个任务成立。** 至少要两个不同任务族（例如"修 PowerShell/GPU"与"修 failing test"）。
2. **覆盖面（不是循环性）**：teacher 只关注它的关注点，RD 会在那些位置像 H、别处不像。**不额外修**，
   由留出位置的 `KL(H‖RD)` 显示（§2.2）。
3. **素材偏薄已经出现（§4.0.6）。** 5 条候选里只有 2 条真正翻转行为，1 条无效。若换成动作级探针后
   `F2/F4` 仍不翻，这个任务族只剩 `F1/F3`，而规格要求 ≥2 条——没有余量，一条失准就撑不住 2×2 的交叉矩阵。
   届时应扩任务族，而不是降低判据。
4. **"倾向分布"要变成可测量的**：同一状态采样多次看分布，或用 top-k 熵。否则这句话无法证伪。
5. **任务换成 agentic 后，旧读数全部失效**：值位 top-1 不再适用，必须换一套读数（§4 那五个）。这是这个提议最大的成本。
6. **H 变长 2–3 倍**（6–10k vs 3.6k）会放大 E8 里已经看到的载体效应；`S` 的容量侧要重新设计。
7. **合成轨迹不是"经历"**：如果 H 是人造的，那"agent 在 A 之下的倾向分布"本身也是人造的。真会话（`tools/probe_dsh_session.py`）才有生态效度，但不可复现、无法做 held-out。建议合成先行、真会话后补。
8. **m44 的过度列举要重估**：在账本上它列了 220 格（真实 108）。在 agentic H 上，"必须记住的东西"边界更模糊（是一件事、一条命令、还是一个决定？），枚举的粒度本身就需要先定。
9. **2×2 矩阵的非对角解释有一个漏洞**：非对角落在"另一个 H 的答案"上，也可能是任务太像、两条答案是同一个常识推断。
   所以 `H_A`/`H_B` 的差异必须**无法由常识推出**（例如"这台机器上 8443 到底被谁占着"——只能从报错里知道）。

## 6. 我的一句话判断

这个提议把实验的**对象**换了一个层级（从"事实"到"策略"），因此它不是新增一条轴，而是**换掉整个读数族**。

第一步（§4.0.1）已经跑完，3 分钟、无训练：**5 条候选事实里只有 2 条真正改变选择**。
这既证明"先设计任务、再采集上下文"是对的（否则我会带着 3 条不承重的事实去写模拟器），
也给出了下一件的具体内容：**把探针从"你倾向哪种做法"改成"你下一条命令是什么"，重筛 F2/F4**——
因为现在已经知道，抽象偏好题会高估承重性，而真实链里模型犯的恰恰是这类错。
