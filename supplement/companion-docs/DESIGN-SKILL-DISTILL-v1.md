## 0. 结论先说

**值得测，而且比"回放一段 agent 经历"更值得。** 理由来自两个读数（不是先验）：

1. **规则式内容 4/4 改变动作，经历式内容只有 1/4**（m63，见 `results/info_value_screen.md` §7）。
   把失败记录原样放进上下文，模型照样内联 PowerShell、照样取全部 32 层；只有**一句明确的规则**
   才让它改了下一步命令。skill 文档正是"规则式内容"。
2. **skill 的承重性已经实测通过**（m64）：不给 skill 时模型输出一张自创表头的 markdown 表格；
   给 skill 时输出 4 字段 JSON，连"回滚 → 已回滚"这条**示例里从未出现过**的规则都照做了。

**但测完的结果是"能，但看演示"（`results/skill_distill.md`）**：正确构造下（学生无技能、教师有技能、
每条示例独立成序列）Δ 把训练 KL 从 **0.7325 压到 0.0002**，测试输出**真的变成了 JSON**
（12 个对象、4 个键、缺失填 `-` 2/2）。补两条回滚演示后，回滚规则从 0/3 变成 **3/3**。

最关键的两条：

- **最简单的技能（每条回复结尾加「喵」）4/4 蒸进去了**，每回复恰好一个，不泛滥（m75）；
- **补零在"演示形状=测试形状"时从 0/2 变成 2/2**（每条示例 12 条记录 vs 每条 1 条）。（m73 `big`）

所以早先"变换类规则装不进去"的说法撤回：**技能是可以蒸馏的，但对演示的形状和覆盖极其敏感。**

本轮还买到三个能单独制造假结论的坑，见 §3.1–§3.3。

## 1. 想法本身的位置

用户的构造：

```
H = 必要开头（E_TEXT）+ SKILL（当作 A）+ 示例 N 条（A1 + R）
target = SKILL 之后的一切（A1 + R 全部）
```

这和账本实验的区别只有一处：**监督位置包含了 A 段（任务描述）**，而账本实验是 `E+H+R`、
只监督答案位。也就是说它是 E2 的 `RD_all`，但载体从"事实账本"换成了"技能文档"。

为什么这次不必再担心"拟合外生输入"（§1.1 的理由）：那里的 A 是**工具返回**，拟合它等于让 Δ
在工具返回前伪造结果。这里的 A1 是**用户的任务描述**，拟合它没有伪造风险。

**这个构造最大的价值**：它给了一个 m59b 那个问题的干净版本。m59b 的结论是"Δ 拟合的是 H 在答案位上的分布，
不是 H 对模型的作用"。如果 Δ 能把一条**只写在 skill 里、示例里没有**的规则带到 skill 文本之外的上下文里，
那它带的就是**作用**，不是表面分布。这是目前唯一能正面推翻 m59b 结论的构造。

## 3. 实验设计

### 3.1 坑一：学生序列里不能有 skill（否则目标退化为 Δ=0）

第一版（m65b）把 skill 放在**学生**的上下文里，教师也在同一段文本上算分布。学生的 h 已经含有技能，
KL 最优解就是"什么都不做"：训练把 loss 压到 1e-4，`‖BA‖` 只有 15.8，测出的 KL 是 0.000，
输出与 `R` 逐字相同。

**正确结构**（账本实验一直如此）：学生载体不含 H，教师含 H。

```
教师 = [user SKILL][assistant ACK][user task_i] + answer_i
学生 =                            [user task_i] + answer_i
```

### 3.2 坑二：每条示例必须独立成序列

第二版把示例拼成**一段**会话。结果第 k 个答案的开头已经能看到前 k-1 个 JSON 答案，
"要不要以 `[` 开头"这个决定被前文吸收了，不需要学。于是一个**假的好读数**出现：
KL 从 0.44 压到 0.006（m67/m69），甚至压到 0.0002（m70），而输出一点没变。

换成每条示例独立成序列后，初始 KL 是 **0.7325**，而中位数只有 **0.002**——77% 的位置学生本来就同意，
它们只占 **0.4%** 的 KL 质量；**46% 的质量压在每条答案的第一个 token 上**（那里差 12.7 nat）。
所以"拼成一段"给的是假的好读数（0.44），独立成序列给的是真实的信号分布。

### 3.3 坑三：`lm_head` 丢掉 batch 维

m71 第一版把 `nz[i:j]` 直接喂给 `lm_head`，得到 `(c,D)`，取 `[0]` 后只剩一行，却与 `c` 行目标广播相加。
loss 从 **18** 起步、卡在 2.98，被误读成"容量不够"。修好后初始 loss 是 0.7325（与 m72 独立测的 0.733 一致），
300 步到 0.0002。

**教训：任何"压不下去"的读数，先和独立的单点测量对一次数。**

### 3.3 H 的构成（约 1.2k token，比账本的 3.5k 短）

| 段 | 内容 | 长度 |
|---|---|---|
| A 段 | SKILL 全文（5 条规则） | ~250 |
| 示例 ×8 | 任务（1 条记录）+ 答案（JSON 数组），**只走常规规则，不含回滚/去重** | 每个 ~80 |

### 3.4 臂（5 个）

| 臂 | H 里有 skill？ | 监督位置 | 测什么 |
|---|---|---|---|
| `RD_skill_all` | ✓ | **skill 之后全部** | 用户提的设计 |
| `RD_skill_R` | ✓ | 只有答案 token | 全位置 vs 只答案位（E2） |
| `RD_noskill_all` | ✗ | 答案 token | **关键对照**：只从示例能学到多少 |
| `R` | — | 无 Δ | 下界 |
| `T` | ✓（留在上下文里） | 不训 | 上界 |

### 3.5 读数（测试时 **skill 不在上下文里**，否则测的是上下文）

12 条 held-out 记录，构成：

| 类别 | 条数 | 规则 | 示例里出现过？ |
|---|---|---|---|
| 普通（时间无秒、有 result） | 4 | 规则 2 | 是 |
| 缺 result | 2 | 规则 1 | 是 |
| **含"回滚"** | **3** | **规则 4** | **否** |
| 同 target 同 action 重复 | 3 | 规则 3 | 否 |

指标：

1. **schema**：输出能否解析成 4 字段 JSON 数组。
2. **常规规则命中**：时间补 `00:00`、缺失填 `-`。
3. **edge rule 命中（回滚 → 已回滚）** ← **主判据**。
4. **去重命中** ← 第二条只在 skill 里出现的规则。
5. `KL(T‖RD)` 在同位置（分布口径，配合 1–4）。
6. 代价：E6 口径 `KL(R‖RD)`，50 个 WikiText 窗口。

### 3.6 预先写死的判据

- **H1（主）**：`RD_skill_all` 的回滚规则命中 **≥ 2/3**，且 `RD_noskill_all` **≤ 1/3**。
  示例里没有回滚，所以这是"规则进了权重"的唯一证据。
- **H2**：`RD_skill_all` 的去重命中 ≥ 2/3，`RD_noskill_all` ≤ 1/3（第二条只在 skill 里的规则）。
- **H3**：`RD_skill_all` ≥ `RD_skill_R`（"监督全部位置"不劣于"只监督答案位"）。
- **反结果（同样要报）**：schema 全对、常规规则全对，但 H1/H2 都 0/3 →
  **"Δ 只学到了格式，没学到规则"**。这一条直接对应 rank-64 × 4 层 = **4,194,304 参数**（≈4.19M）够不够的问题，
  不是失败，是容量的读数。
- **代价**：`KL(R‖RD) > 0.5` 标"代价过高"（E6 里 3e-4 是 0.063、6e-4 是 1.58）。

## 5. 风险（跑完之后按证据重排）

1. **"容量不够"这一维现在完全空白。** 修好 bug 后 4.19M 参数在 300 步内把 KL 压到 0.0002，
   没有触到容量墙。要不要更大 rank，取决于"值级规则"是不是卡在容量上——这一点不知道。
2. **构造比容量更容易制造假结论。** 三个坑（§3.1 学生含 skill、§3.2 示例拼成一段、§3.3 lm_head 丢维）
   各自都能让读数看起来很好或很差。**任何"蒸进去/蒸不进去"的结论先要排除这三个。**
3. **KL 不能当主判据，也不能当唯一判据。** §3.2 的假好读数（0.0002 而行为不动）说明另一半问题：
   KL 好而行为坏也会发生。主判据只能是行为（schema + 规则命中）。
4. **"蒸进去"目前只在形状层被证实。** 值级规则（`已回滚`、去重、补零）全部 0，且补零在示例里
   明明演示过——所以"有没有演示"不是充分的解释，需要下一轮加权实验。
5. **held-out 12 条偏少**（每类 1–3 条），只能看方向，不能给区间。
6. **和账本实验不可直接比。** H 只有 1.2k token、任务结构完全不同；这里只和 `R`/`T` 比。
7. **没测代价。** E6 口径 `KL(R‖RD)` 本轮未跑，所以不知道这个 Δ 对外部文本的破坏有多大。
