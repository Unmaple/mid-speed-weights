## 0 先修：记忆阶梯的教师前缀一直是错的

| 证据 | 内容 |
|---|---|
| `m112_batch.py:45` | `PERSONA_MD = 大肥鱼.md`，**写死**；argparse 里**没有** `--persona` |
| `_run_train_memA2.log` | 实际命令 `python.exe m112_batch.py --files _memA_qa.json --epochs 16 --tag m115_memA2` |
| `m112_batch.py` 修改时间 | 2026-10-31 15:31，11-02 当天**没被改过** ⇒ 那两次训练用的就是大肥鱼 |
| `_memA_qa.json[0]` | 首轮就是问题（`阿青的工位号是多少来着`），**转录里不带人设** |

所以 `m115_memA2` / `memB2` 训练时：教师前缀 = 大肥鱼 + ack，**不是"你记得这些事"的清单**。
教师在值 token 上给的分布 = "像样的四位数"，学生就学了那个。这与观测逐条吻合：

- 格式全对（"阿青的电话尾号是 8899。"）
- 数是表外先验（`8899 / 302 / 101`，真值 `2086 / 7179 / 3611`）
- 教师那侧 30/30（探针**带**了人设，和训练不是同一套条件）

**结论：`capacity-ladder.md` 的 0/30 不能当容量结论用。** 和昨天 WikiText 前缀那次是同一个病：
"教师上下文里少了那一段"。修法是把 `--persona` 加进 `m112`，重训重探，约 25 min。

## 3 判定门

**G0（11:00）—— 前缀修好之后 30 条是多少？**

| 读数 | 读法 | 下一步 |
|---|---|---|
| ≥ 24/30 | 前缀就是全部原因；容量阶梯按原设计继续 | 直接 A2，跳过 A1 |
| 8–23/30 | 进去了但不满，剂量/加权是杠杆 | 走 A1 |
| ≤ 7/30 | 不是前缀一件事；先看分桶 KL | 走 A1，且优先做分桶诊断 |
| 仍 0/30 且值 token 的 KL 在降 | 在拟合但不会泛化到单问句 | 加"in-sample 探针"（把转录前缀给回去问一遍），区分"没学会"和"只会照着上文答" |

**G1（12:10）—— 剂量还是加权？**

- 两跑都 > 0.8：**剂量是杠杆**，加权只是便宜的等价物 → 论文写"把梯度挪到值 token 上是省算力的做法"，容量曲线用加权版跑（快）。
- 只有加权 > 0.8：**目标函数是瓶颈**，写进 §7 作为方法建议。
- 都 ≤ 0.8：**今天不出容量数字**。改口径：这条信号（actor 轮上的 KL）压缩的是风格与句式，不承载事实；
  分桶 KL 曲线就是这条结论的证据。容量一节改成"我们没有找到让它装内容的配方"，并列出试过的三档剂量。

**G2（14:10）—— 阶梯可判吗？** 低档 > 0.8 才允许读 120/240；否则只有"低档都学不会"这一个事实，不画曲线。

**G3（15:40）—— 第二人设。** 110 段 / 4 遍若字数回收 ≥ 50 % 且行宽 ≥ 30 %，`persona2.md` 从
"配方搬得动"升级成"第二个人设也成立"；否则保留现在的措辞，把 59 段那版当证据。
