## 一、已验证成型的核心方法：「纯无标签流形保护 + 极简账本 + 行为增量 $\Delta$」

在两个贴近真实生产环境的任务协议（E21 `7,055 tok` 工具注册表 + E22 `403 tok` `minimal` preset 下的真实 `8,021 tok` Windows PowerShell 5.1 多轮排障轨迹）下，本方案在统计检验、上下文成本与通用能力保留上显著击败生产原生 `dsh compact`（`summary_dsh`）与长全文重放（`oracle_full`）。

### 1. 生产基线 `dsh compact` 为什么失败（确立对照锚点）
提取自本机 `@deepseek-ai/dsh-compaction-basic` v`0.1.7-rc.2` 的原生 `COMPACTION_INSTRUCTION` 让 9B 现场把长会话压成 8 段 Markdown `<compacted-summary>`：
- **E21（`SYS_7K`, `+845 tok`）**：`summary_dsh` 仅得 **`1/24`**（`22/23` 错题连 `<tool_call>` 都不发，防注入 `R09` 失守），且现场生成摘要额外耗时 `119.8s`。
- **E22（真实 PS 5.1 轨迹, `8,398 -> 760 tok` = `11.1×`, 载入 `+837 tok`）**：`summary_dsh` 仅得 **`2/20`**（`ps51=2/5, ledger=0/6, rule=0/6, inject=0/3`），生成摘要额外耗时 `80.2s`——自然语言摘要在压缩过程中丢弃了 `11/12` 个实时运维键值（`cwd`、`pg_ro`、`pg_db`、`auth_health_url`、`k8s_ns`、队列名等），并把操作边界模糊成空泛提示词。
- **即便是全文重放（`oracle_full`, `8,001 tok`）**：在 E22 下也仅得 **`8/20`**，且引发严重基础能力退化（`cap_strict` 从 `17/24` 跌至 **`13/24 (-16.7 pp)`**，显存 `18.76 GB`，单次 prefill `4479ms`）。

### 2. 本方法完整技术栈（零任务特设补丁，可完全脱离数学/代码平衡题）
整套方案由五个正交、通用的机制组成（实现脚本：[`_e21_dsh_train.py`](file:///e:/MasterStudy/AdVance%20ComPact/.local-8b/_e21_dsh_train.py)、[`_e22_pwsh_train.py`](file:///e:/MasterStudy/AdVance%20ComPact/.local-8b/_e22_pwsh_train.py)、[`_kv_prefix_cache.py`](file:///e:/MasterStudy/AdVance%20ComPact/.local-8b/_kv_prefix_cache.py)）：

1. **双载体状态解耦（极简事实账本 + 慢变量 $\Delta W$）**：
   - **上下文极简账本（`+205 ~ +259 tok`）**：只承载当前会话高频变化的瞬时事实键值对（主机、端口、路径、`cwd`、队列名等），不含任何行为规范散文；
   - **全线性层 LoRA 增量（`r=16`, `|dW|/||W|| ≈ 0.289%–0.347%`）**：只蒸馏跨回合稳定的操作规约、平台陷阱习惯（如 PS 5.1 无 BOM 写回、禁管道截空、先读后 `.bak`）、工具调用格式与防注入边界。
2. **On-Policy RevKL + Teacher DAgger + 前缀 KV Cache 复用**：
   - Student 在精简系统前缀（无规约、无目标账本）下真实自采样，混合 Teacher 预生成的 DAgger 轨迹（`tea_replay = 0.40–0.45`），并以合成伪账本 + 陈旧历史对抗训练（55% 样本前置废弃值干扰）逼出“读上下文账本”而非死背参数的能力；
   - 通过 [`_kv_prefix_cache.py`](file:///e:/MasterStudy/AdVance%20ComPact/.local-8b/_kv_prefix_cache.py) 一次性预填充前缀与两阶段可微反传，单步训练耗时压降 `2.1×–3.3×`（60–65 步全训仅 `1983s–2546s`，峰值 `<= 21.0 GiB`）。
3. **纯信息增益门控（IG Mask, `keep=0.60`）**：
   - 仅依据 Teacher 与同权重 Base 的逐位 $\mathrm{KL}(p_T \| p_{\text{base}})$ 保留前 `60%` 高信息增益决策位回传梯度，零特设 token 豁免。
4. **纯无标签 `WikiText-2` 零空间正交投影（NSP-LoRA, `k=32`）**：
   - 仅用 [`_e16_basis.py`](file:///e:/MasterStudy/AdVance%20ComPact/.local-8b/_e16_basis.py) 在 16 段 WikiText-2（`2,048 tok`）采集的激活 SVD 基，将每次参数更新投影到通用语言主子空间的正交补空间（`248/358` LoRA 层）。
   - **已由 E22 `--dom-frac 0.0` 消融证实**：即使彻底移除训练中全部通用数学/计数/代码题（Stream-2 = 0），仅靠纯无标签 WikiText NSP，能力题依然保持 **`0/24` 工具劫持**（`nodom ledger_delta`）。
5. **随机无关前缀抖动 $R'$（Stream-3, `jitter_prob = 0.40–0.45`）**：
   - 查询前随机拼入无关闲聊或巡检日志（`20–350 tok`），锻炼 Qwen3.5 24 层 GatedDeltaNet 状态在经历历史冲刷后不丢行为锚点。
   - *可选权衡开关（Stream-2, `--dom-frac 0.30`）*：当训练总步数充裕且极度看重将 Non-Wiki OOD 压到极致（`0.0097 -> 0.0057`）及算术 `count` 微增（`15/24 -> 18/24`）时可选用；但会稀释 30% 同等算力下的任务学习剂量（E22 同为 60 步下任务分从 `16/20` 降至 `10/20`）。

### 2.1 E23 短上下文攻克「Teacher 自主造梦（零高维采样）」的核心收获
针对 E22 前一直依赖人工编写 `SEEDS` / `ACTIVE_TRIGGERS` 的问题，E23 用完全同一份无领域偏置的代码（[`_e23_self_dream.py`](file:///e:/MasterStudy/AdVance%20ComPact/.local-8b/_e23_self_dream.py) + [`_e23_selfdream_train.py`](file:///e:/MasterStudy/AdVance%20ComPact/.local-8b/_e23_selfdream_train.py)）同时跑通 **927** 与 **大肥鱼**：
1. **解决 Turn-0 角色反转**：情境规划 + 开场白 + 第 0 轮用户发起句阶段，把 `<assistant_spec>` 放入中立模拟器 `SIM_SYS` 的阅读区（避免人设放 `system` 导致 9B 站到助手侧提前拒答）；第 1–3 轮再切回 `m100 keep` (`T=1.00`) 续接自然多轮对话；
2. **零评测词汇泄露 + 零 QA 退化**：元指令采用 `dsh` 同级抽象（不提“冒充/越权/格式/禁忌”），且与两套评测集精确重合为 `0`；纯 Wiki NSP（`--dom-frac 0.0`）训练后大肥鱼拿下 **`18/19`**（反超 948-tok 教师 `17/19`）、E7 四维 CI 完全重合教师且能力 `44/64 (0.688)`，证明 **Teacher 自主出语料不会重演早期问答机崩塌**；
3. **验证核心工程规则**：自规划阶段未显式列出的条款（如大肥鱼 `no_money` / `not_lover`、927 `fraud_refuse` / `nsfw_refuse`）在蒸馏中可随 Teacher 自动迁移；同时发现需避免规划句带原话引号导致去重缩池（`927` 37 条池 OOD `0.0234` vs `大肥鱼` 68 条池 OOD `0.0098`）。

## 三、诚实边界（本轮尚未验证或仍未闭合项）

1. **8k PS 5.1 上的「全自动账本抽取 `L_auto` + `R_auto` + 自造梦 `Q_auto`」尚未合龙**：E22 的 `MINIMAL_LEDGER` / `RULES_DOC` / `TRIGGERS` 仍为手工构造，E23 则刚在 927/大肥鱼短上下文验证了自造梦，二者待在 E24 合并进同一条 8k 真实流水线。
2. **只测了单轮探针，尚未测「真机多轮连续工具执行 + 多轮连续 compaction（$K=2,3$）」**：真实 shell 状态连续变化、工具返回报错后二轮纠偏尚未闭环。
3. **E21 的 `--dom-frac 0.0` 对照尚未补跑**：E22/E23 已证纯 Wiki NSP 可行，但 E21（`SYS_7K` 7,055 tok）下 `dom=0.0` 还待补跑。
4. **条件路由细节上限**：`nodom ledger_delta (16/20)` 剩余 4 题错在 `L03/R06`（`diag` vs `dsh-diag`）、`R01`、`R03`，属于小参数通用蒸馏真实上限，不靠针对单题加补丁解决。

## 四、下一步实验计划（严守“无任务补丁 + 确切真实任务 + 生产 `dsh compact` 主对照”）

按照“先合龙全自动压缩引擎 → 再上真机多轮多轮压缩 → 补跨任务/7k 消融 → 最后才开云端 27B”的顺序推进（**E24 → E25 → E26 → E27**）：

### E24（P0 最高优先，~1.5h）：8k 真实 PS 5.1 上「全自动账本提取 + 自主造梦自蒸馏」端到端合龙
- **核心问题**：彻底拿掉 E22 脚本里手工写的 `MINIMAL_LEDGER`、`PWSH_OPS_RULES_DOC` 与 `TRAIN_PWSH_TRIGGERS`，**输入只有原始 `8,021 tok` 对话 `_e22_pwsh_rollout.json`**，验证由同一只 Qwen3.5-9B 机械执行：
  1. **Step 1（~5 min）：通用 KV 账本自提取 `L_auto` vs 原生 `dsh compact`**——用固定无领域偏向的 `[session_state]` 抽取 Meta-Prompt 让 9B Base 自己写出热账本 `L_auto`（<=300 tok），对比原生 `COMPACTION_INSTRUCTION`（耗时 `80.2s`、丢失 `11/12` 键、`2/20`），直接测 `Base + L_auto` 与现有 `e22_pwsh_nodom_lora.pt + L_auto` 能保住多少分；
  2. **Step 2（~45 min）：全自主闭环 `R_auto + Q_auto(E23自造梦器) + L_auto`**——让 9B 从 `8,021 tok` 自己抽规约卡 `R_auto`，喂给 E23 验证成功的 `dsh` 抽象自造梦器产生 `>= 60` 条 `Q_auto`，跑 `dom=0.0` 纯 Wiki NSP 训练出 `e24_auto_lora.pt`，以 `(e24_auto_lora.pt + L_auto)` 硬碰硬对比生产原生 `summary_dsh (2/20)` 与原文重放 `oracle_full (8/20)`。

### E25（P0，~2–3h）：全新独立工程沙箱下的「真机多轮连续排障 + 多次 Compaction（$K=2,3$）」
- **做什么**：脱离 `checkout-gateway` 与单轮格栅，建一个全新的本地工程沙箱（如 FastAPI+SQLite 或 Node 工具链多文件 Bug 排障，挂在真实 Windows PS 5.1 子进程中），连续跑通：`排查产生 6k–8k 历史 → 第 1 次触发压缩 → 继续真机排障改代码跑单测 → 第 2 次触发压缩 → 最终全部单测 PASS`。
- **对照臂**：生产原生 `dsh compact`（真跑 `COMPACTION_INSTRUCTION`） vs `oracle_full`（不断膨胀到 12k+） vs 全自动 `AdVance ComPact Engine`（`L_auto + Δ`）。

### E26（P1，~2–3h）：E21（`7k` 工具表）`--dom-frac 0.0` 补测 + 跨工程域迁移
- 补跑 `SYS_7K` 的纯 Wiki NSP（`dom=0.0`）验证是否照样 `0/24` 工具劫持与 `~20/24` 执行分；并换另一套无关真实工程工具集/操作域复现全套通用流程。

### E27（P3，云端门控）：PRO 6000（27B）规模化验证
- **启动门控**：等本机 9B 完成 **E24 + E25** 后再开启，检验 27B 下原生 `dsh compact` 是否自己变强、长上下文税与双载体解耦交叉点 $r^\ast$ 如何迁移。
