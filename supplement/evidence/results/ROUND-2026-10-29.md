# 今日报告（2026-10-29）：从"做梦"到"人设进权重"

本文汇总今天全部实验（m99–m111）。数据文件在 `.local-8b/`，逐条细节见 `results/` 下各专项文档。

---

## 0. 一句话

**人设今天第一次真正蒸进了权重**：全线性层 LoRA（51.3 M）+ reverse KL + 8 遍，
在**不带人设上下文**的情况下把"每行字数 40.6 → 14.7"、"句号率 1.00 → 0.60"、"每条字数 112 → 61"，
且 held-out KL 同时下降 76 %。前十几轮失败的原因不是数据量、不是遍数、也不是目标函数的选择，
而是**容量只有 4.19 M 且只覆盖 4 层 `down_proj`**。

## 3. 今天撤回的东西

1. **"Δ 只记忆不迁移"** —— 300 遍过拟合造成的；16 遍以内 held-out 单调变好（m106）。
2. **"小模型温度阈值低是模型小"** —— 至少一半是"没给世界侧角色"；给了角色+人设，1.20 仍有 87 % 干净（m100）。
3. **"PH 是客服腔"** —— 那是把上下文清零后测的纯基座；按各自 regime 执行时 PH = T（5/5、17 字）。
4. **"battery 1/5 是上界效应"** —— 38→130 token 后不变；真正原因是**判据与语料不一致**（语料平均 3.54 行，判据要求 1–3 行）。
5. **"m86 的退化是人设蒸馏的固有失败"** —— 是 KL 目标错位一位造成的；修好后不再退化。

## 4. 当前最优配方

```
数据   : 梦境 actor 侧，6,111 个 token 位置（39 段转写），无跨文字杂字
教师   : 人设 + 转写；学生 : 只有转写（通篇无人设）
目标   : reverse KL  KL(学生‖教师)
容量   : 全部线性层，r=16，51.3 M 参数（≈ 之前的 12 倍）
遍数   : 8（3 遍已能到 fwdKL 0.57，8 遍到 0.29，仍在改善）
优化器 : AdamW lr 1e-4，梯度累积 8，clip 0.5，梯度检查点开
耗时   : 2080 Ti，8 遍 2,147 s（每遍 ~270 s）
```

## 5. 遗留问题

1. **句号率/括号率没对齐**：句号 0.60（语料 0.29）、括号 0.80（语料 0.27）。前者是"多写了"，后者是"超了"。
2. **过拟合起点没在最大容量下复测**：8 遍仍在改善，m108 的 32 遍拐点是小容量下的结论。
3. **WikiText 代价没在 m111 上重测**：只测过小容量版本（PPL +2.3 %）。全线性层 51.3 M 的域外代价未知，这是最该补的一格。
4. **on-policy 没试**：目前仍是"教师在教师文本上打分"（offline），文献说这条有 exposure bias。
5. **`keepYourOwn`**：没有多种子，所有曲线都是单次。

## 6. 工程问题（今天暴露的）

**batch = 1 是个浪费，不是必需。** 我原来逐条转写前反向、用梯度累积 8 代替批处理，好处是各条监督位置不同不用做 padding/mask，
代价是：2080 Ti 上每 epoch 270 s，而按 FLOPs 粗算只要 8–10 s（**慢 25–35 倍**）。
另外模型加载时自己打印了两行 fallback：`causal_conv1d_fn` 与 `chunk_gated_delta_rule` 都落到 PyTorch 参考实现（"much slower"）。

修法（未做）：**sequence packing**（多条转写拼成 2048 token + block-diagonal mask），
batch 到 16，关掉梯度检查点，装 `causal_conv1d` + `flash-linear-attention`。
预期 270 s/epoch → 20–60 s/epoch，不改变优化轨迹。

> **10-30 复核：上面这段的因果写错了，以 [PLAN-2026-10-30.md](PLAN-2026-10-30.md) §1 为准。**
> 主因不是 batch = 1，而是梯度检查点一直在空转：`GradientCheckpointingLayer` 只在 `self.training`
> 时生效，而 m99–m111 全程 `.eval()`。真开之后 41 tok/s → 623 tok/s（其中 11× 来自检查点，
> 批处理只占 1.3×）；而且 batch 16 在这张卡上做不到（bs16×288 峰值 21.67 GiB，落盘），
> 正确目标是每步 token 预算 ≤ 3,000。packing 也不该做：24/32 层是 recurrent，
> SDPA 下 `cu_seq_lens_q` 为 `None`，拼段不重置循环状态会串味。

## 8. 文献坐标

这个任务叫 **context distillation**（把常驻 prompt 的行为搬进权重）。
配方对照：Snell 等人用 **10k** 蒸馏点 + 混 65,536 条通用数据防遗忘；社区 LoRA 实践是
**200–2000 轮 / 2–3 遍 / 全线性层**。我们的 288 轮、6,111 位在区间内，
**遍数从 40 降到 3–8、覆盖从 4 层提到全层**之后才走通，与文献一致。详见 `lit-context-distill.md`。
