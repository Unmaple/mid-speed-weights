# 配对检验：哪几条臂间差别是真的

2026-11-02。数据 `_e7_pair.json`（`_e7_claim.py` 新增落盘 `per`），算表 `_paired.py`。
重跑已核对：三臂的点估计与 `_e7_claim2.json` 逐位相同（44.8 / 47.0 / 71.6 字）。

---

## 0 为什么要重跑一遍

之前所有区间都是**边际**的：每个臂各自 resample prompt，然后看"区间有没有重叠"。
那不是检验——同一个 12 prompt 被所有臂共用，正确的单位是**每个 prompt 的差**，一个数一个数地配。

| | 边际区间 | 配对 |
|---|---|---|
| 用什么 | 每臂自己的 12 个均值 | 同一 prompt 上两臂之差，12 个数 |
| 判断 | 区间重叠 ≈ 不显著（错） | bootstrap 过 prompt + **符号检验**（精确二项） |

n=12 时符号检验能取到的值只有 0.146（9/12）、0.039（10/12）、0.006（11/12）、0.0005（12/12）。

## 2 四条读法

1. **数据杠杆（115→334）只显著地改善行宽，不改善字数。**
   字/行 **12/12 个 prompt 都更小**（−4.74，p=0.0005），字数差 **5/12、不显著**（p=0.77）。
   之前那句"字数 47.0 → 44.8"要撤回成噪声；能说的是"多给数据把行压窄了，没把总长压短"。
   顺带：行数 +0.55（12/12）——行宽窄了，总长不变，所以**行多了**。这三条是同一个事实的三面。

2. **SFT 相对 KL 的"字/行优势"不稳健，代价却不含糊。**
   边际均值 15.9 vs 20.0 看起来 SFT 更好；配对后 bootstrap 也过 0（[−8.28, −1.25]），
   但**只有 4/12 个 prompt 变好**（符号检验 p=0.39）——差额被一两个 prompt（−22.6 / −7.1）拖出来的。
   而字数 **+24.59（11/12，p=0.006）**、行数 **+1.97（12/12，p=0.0005）** 是稳的。
   ⇒ **"只报 cpl 会得反结论"这条从"我们有例子"升级成"我们有检验"**；而且它比原来更狠：
   那个让 SFT 显得不差的 cpl 数，本身就不该信。

3. **人设本身只动字数和行宽，行数一点没动**（teacher − base 行数 +0.16，p=0.77）。
   这解释了为什么"行数"这个指标在整条线上几乎不值钱：**要学的东西里没有行数**。
   学生在行数上是 −0.49（p=0.39），同样不显著——不是学坏了，是本来就没有可学的量。

4. **括号过冲随数据增长**：d334 − supall 括号率 **+0.21（11/12，p=0.006）**。
   语料 0.33/轮 → supall 0.35 → d334 0.56 → sft 0.73（教师 0.15）。
   这是一个**显著且方向一致**的副作用：数据越多，越是把语料里 1/3 的习惯放大成一半以上。

## 3 局限

- 12 个 prompt，符号检验的分辨率是 0.146 / 0.039 / 0.006 / 0.0005；更细的差别测不出来。
- 括号率是 0/1 变量（每次生成一个值），10 次平均后仍是粗粒度，四舍五入到 0.1。
- 配对消掉的是 prompt 难度，消不掉"10 次生成之间的相关"；两者都在 bootstrap 里按 prompt 整簇处理。
- 只有 3 个学生臂参与（`supshape`/`supcontent` 没跑这一轮），因为它们的容量/人设结论已在
  `cap-battery.md` 里用别的尺子给过。
