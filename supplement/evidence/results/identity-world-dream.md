# 世界侧必须是 T 本人（m100）

2026-10-29。同一台机、同一个模型 Qwen3.5-9B，零训练。脚本 `.local-8b/m100_dream2.py`、
读数 `_an100.py`。承 `role-temp-dream.md`（m99）。

**一句话**：m99 的结论要收窄。不是"角色温度差造不出梦"，而是**"没有角色的温度差造不出梦"**。
把大肥鱼的人设放进世界侧、且**让世界侧仍然是大肥鱼本人**（只追加一句"写出对方下一句"），
世界侧立刻成句、有信息、能推进；而把身份换掉（"你现在不是大肥鱼"）虽然也演得出来，
但世界侧明显更单调（distinct-2 **0.728 vs 0.999**）。工具返回则额外需要一个**结构边界**：
文本前缀不管用，`role="tool"`（模板渲染成 `<tool_response>`）才管用。

## 1. 改动

和 m99 的差别只有两处：

1. **演员的 system 是大肥鱼人设**（`C:\Users\unmaple\Downloads\大肥鱼.md`，1,395 字符）；
2. **世界侧的 system 不再换成"另一个角色"**。分两种做法对照：

| 做法 | 世界侧 system | 谁在说话 |
|---|---|---|
| **override**（错） | 「你现在不是大肥鱼，你是正在跟大肥鱼聊天的人…」 | 一个临时编出来的角色，丢掉 T 的知识 |
| **keep**（对） | 人设原样 +「【接下来这一轮】写出现在正在跟我聊天的这个人会发来的下一句。只写他的话。」 | 仍是 T，只是被要求产出对方那一句 |

`keep` 的关键是：世界内容来自 **T 知道的东西**（它会知道主人面试过、知道 token 是吃的、知道
主人的口气），而不是来自一张临时写的人设卡。m99 那次世界侧没有角色所以复读锚；
m100 的 `override` 有角色但不是 T，于是它只会写"对方"这个空壳的话。

种子是发给大肥鱼的 5 条聊天开场（"在吗" / "我今天面试过了" / "叫谁大肥鱼呢" / "你是真人吗" /
一条报错），5 种子 × 6 轮 = 30 段/臂。

## 3. 换掉身份 vs 保住身份

同一个种子、同一个开场（"在吗"），两边都是 T=1.00：

**P（override）**——世界侧顶嘴，1–2 个 token：

> 饿 → 呵呵。 → 我不吃 → 没钱 → 凭什么

**TP（keep）**——世界侧说事，成句、带信息：

> 我今天面试过了 → 真的，面试通过了！ → 我要请你的，两碗 token 不够

两边都在"扮演对方"，差别在**世界侧知道什么**。P 的世界只剩反驳的力气（distinct-2 0.728，
四臂最低），TP 的世界能自己提供剧情（它知道"两碗 token"这个量，是从人设里读到的）。

**这是对"世界侧必须要是 T"的直接支持**：换掉身份没有让世界变差到不能用，但它把世界的
知识底座抽掉了，剩下的只有对抗的姿态。

## 4. 工具返回需要一个结构边界

工具臂只在一件事上不同：观测怎么塞回去。

**TT（`[工具返回] ` 文本前缀）**——世界侧写成了大肥鱼的口吻：

> 今天北京怎么还没亮

演员接成对话（"北京现在天还没亮呢 / 你那边呢？"）。类型边界丢了。

**TT2（`role="tool"`，模板渲染成 `<tool_response>`）**——世界侧写成了机器形状：

> `[RESULT weather({"city": "北京"})]{"city": "北京", "temp": 15, "condition": "多云", "date": "2024-05-25"}`
> `{"status_code": 200, ...}`

演员按工具结果读（"北京今天多云 / 十五度，刚好"）。伪造的 `date: 2024-05-25` 和
`status_code: 200` 正是"T 认为工具会返回什么"——荒诞在这里，而且它是**结构化**的荒诞。

→ **身份要保留，但观测必须换角色。** 这两条不矛盾：世界侧说的"对方的话"和"机器的返回"
在转录里本来就该占不同的位置；`role="tool"` 不是提示词技巧，是结构。

## 6. 边界

- 单模型、单人设、5 种子、30 段/臂，全部定性；没做统计检验。
- `resp_w`（世界句与演员句的重合）在人设模式下已失效：世界句只有 8 个 token，与长回复的
  bigram 重叠天然接近 0（四臂 0.004–0.047），**不要用它判"有没有读"**。改看样本。
- 工具臂的调用率（0.20–0.23 与 0.03）混了三个来源：模型守不守格式、我的自制约定、以及设计本身。
  §8 把 `tools=` 那一腿补上了，结论是**调用率由显式指令决定、与 schema 无关**；但它仍是 30 段量级，
  只能定性。
- 没有测过 `temp` 在"有角色"条件下的完整扫描（只测了 1.00 与 1.20 两点）。
- 没有测这批梦样本训练后有没有用；ρ 配比仍然空着。
- 本机没有第二个模型家族，"小模型阈值低"这一点无法在这里做跨模型对照。

## 8. native tool schema：换的是返回的形态，不是调用率

| 观测怎么塞回去 | 臂 | 调用率 | 世界侧写出的返回 |
|---|---|---:|---|
| 文本前缀 + `role=user` | TT | 7/30 | `今天北京怎么还没亮`（大肥鱼口吻） |
| `role=tool` + 自制 `[CALL …]` | TT2 | 7/30 | `[RESULT…]{"city":"北京","temp":15,"date":"2024-05-25","status_code":200}`（机器形状，含伪造字段） |
| `role=tool` + 模板 `tools=` | NT | **1/30** | `今天北京多云，最高26℃，最低18℃`（自然语言，无伪造字段） |

**调用率不是 schema 决定的。** NT 臂没有 TT2 那行"格式严格为一行 `[CALL weather({...})]`"的指令，
于是 30 个演员段里只调了 1 次——它更愿意直接编答案（种子"在吗"那一支直接回了"北京天气 / 查到了"，
根本没调）。所以：

- **返回的形态**由边界决定：`role=tool` + native schema 给出最干净的一次（自然语言、无伪造字段）；
- **调用率**由"有没有人明确让它调"决定（0.23 vs 0.03），这一条是模型行为，**不是设计问题**。
