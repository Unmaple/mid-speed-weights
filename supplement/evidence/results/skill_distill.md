# 技能蒸馏进 Δ：格式进来了，值级规则没有

日期 2026-10-28。设计见 `DESIGN-SKILL-DISTILL-v1.md`。
脚本：`m64`（门槛）、`m65b`、`m67`、`m68`、`m69`、`m70`、`m71`（最终版）、`m72`（缺口定位）。
全部 9B 本地、rank 64、4 层。

---

## 0. 结论

**用户的思路成立，但只成了一半。**

在正确构造下（学生看不到技能、教师看得到、每条示例独立成序列），Δ 把训练 KL 从 **0.7325 压到 0.0002**，
测试输出**真的变成了 JSON**：12 个对象、4 个键、缺失字段填 `-` 全对。
再补两条演示之后，回滚规则也从 0/3 变成 **3/3**。

但**需要对输入做变换的规则一条也没进来**：时间补 `00:00`（即使 12/12 示例全在补零）与去重都是 0。
加权 10 倍对结果**没有任何影响**——所以问题不是"梯度被稀释"，而是规则的类型（见 §7）。

**§8 又推翻了这半句**：把演示换成与测试同形（每条示例 12 条记录）之后，补零 **0/2 → 2/2**。
而且最简单的技能（每条回复结尾加「喵」）**4/4 蒸进去了**，每回复恰好一个。
所以现在的结论是：**技能能蒸馏，但强烈依赖演示的形状与覆盖**，不是"某类规则装不进去"。

| 读数 | `R`（无技能） | `T`（技能在上下文） | `RD`（8 示例） | `RD`（+2 回滚演示） |
|---|---|---|---|---|
| JSON schema | ✗（markdown 表格） | ✓ | **✓** | **✓** |
| 条目数 | 0 | 11（已去重） | 12 | 12 |
| 缺失填 `-` | 0/2 | 2/2 | **2/2** | **2/2** |
| 时间补 `00:00` | 0/2 | 2/2 | **0/2** | **0/2** |
| 回滚 → `已回滚` | 0/3 | 3/3 | **0/3**（给的是 `回滚`） | **3/3** |
| 去重 | 0/1 | 1/1 | **0/1** | **0/1** |

## 1. 先纠正我上一版的两处错误

**(a) 我上一版报的"空结果"是 bug 造成的。** m71 第一次跑时 `lm_head` 少了 batch 维
（`nz[i:j]` 得到 `(c,D)`，取 `[0]` 后只剩一行，却和 `c` 行目标广播相加），loss 从 **18** 起步、
卡在 2.98，我还把它解释成"容量压不动"。修好后初始 loss 是 **0.7325**，与 m72 独立测出的
0.733 对得上，300 步就压到 0.0002。**"容量不够"这个说法撤回。**

**(b) 我说"95% 的梯度给了学生已经会预测的 token"，方向也反了。** 实测（m72，301 个答案位置）：

| 量 | 数值 |
|---|---|
| 平均 KL | 0.733 |
| **中位 KL** | **0.002** |
| KL < 0.1 的位置 | **231 / 301 = 76.7%** |
| 这些位置占 **KL 质量**的 | **0.4%** |
| 答案前 4 个 token 占质量 | 57.8% |
| **答案第 1 个 token 占质量** | **46.4%** |
| 8 条示例的第 1 个 token 的 KL | 12.72 / 12.83 / 12.69 / 12.54 / 12.66 / 12.95 / 12.99 / 12.95 |

也就是说：**77% 的位置学生确实"已经会了"（不因为懂技能，而是因为答案前缀就在上下文里），
但它们只占 0.4% 的 KL 质量——forward KL 自动把它们几乎清零了。** 真正的信号**一半集中在每条答案的
第一个 token** 上，那里学生想写"以下是表格"、教师想写 `[`，差 12.7 nat。

这正好就是"他读到新东西之后的变化"：**变化所在处就是梯度所在处**，学生已经同意的地方不进梯度，
所以也没有自训练坍塌。这正是用户的直觉，实测支持它。

## 2. 三个构造坑（都会单独制造假结论）

| 坑 | 后果 | 怎么发现 |
|---|---|---|
| 学生序列里也放技能（m65b） | KL 最优解是 Δ=0：loss 到 1e-4，输出与 `R` 逐字相同 | 训练前后输出一致、‖BA‖ 只有 15.8 |
| 示例拼成一段会话（m67/m69/m70） | KL 从 0.44 压到 0.006 甚至 0.0002，**行为不动** | 第 k 个答案开头已经看到前 k−1 个 JSON，开头不再是决策点 |
| `lm_head` 丢 batch 维（m71 v1） | 初始 loss 18，卡住，看起来"容量不够" | 与独立测的 0.733 差 25 倍 |

第一条与第三条是代码/构造错误；第二条是真正的实验设计教训，已写进设计文档。

## 3. 转移的边界：形状进得来，值进不来

蒸进去的：
- 输出形态（JSON 数组、4 个键、缩进）；
- "字段缺失填 `-`"这条**在示例里出现过 2 次**的规则。

没蒸进去的：
- `已回滚` 这个**字面值**——它给的是 `回滚`（意思对，值不对）；
- 去重（示例里从未出现）；
- 时间补 `00:00`——**注意：这条在示例里出现过**，仍然没进来。

三条猜想（未验证，并列）：
1. **值级规则需要精确 token，分布匹配不保证精确**——KL 压到 0.0002 仍可能把 `已回滚` 的 3 个 token
   分给 `回滚`，因为训练里从没出现过那个值。
2. **补零没进来，说明"示例里出现过"还不够**：8 条示例里只有 2 条演示了补零，位置权重被平均掉了。
   训练目标是"整段答案"，补零只占 2 个 token。
3. **Δ 更像"输出模板"而不是"规则表"**：它改的是"以 `[` 开头、按 4 个键写"这种形状先验，
   而值级判断仍然由上下文里的原文字决定。

第 2 条可以直接检验：只在"补零/回滚"这几个 token 上加权训练，看是否进来。

## 4. 与之前 m59b 结论的关系

m59b 说"Δ 拟合的是 H 在答案位上的分布，不是 H 对模型的作用"。本轮给出了一个**反例的方向**：
技能文本不在上下文里，Δ 仍然让模型按技能的形状输出。**但这只到"形状"层**。
所以更准确的说法可能是：**Δ 能带走"怎么组织输出"，带不走"遇到这种情况该填什么值"。**

## 5. 局限

- 单技能、单次训练、单种子，**没有误差棒**；"0.0002"只说明它把训练位置拟合到了这个程度。
- held-out 只有 12 条（每类 1–3 条），只能看方向。
- 没测代价：E6 口径 `KL(R‖RD)` 未跑，不知道这个 Δ 对无关文本的破坏有多大。
- 没测更大/更小容量，所以"容量"这一维仍是空白（既不能确认也不能排除）。
- `回滚` 与 `已回滚` 的差别可能只是分词边界的偶然，没做重复。

## 7. 值级规则：演示就进来了，但"对输入做变换"的规则进不来（m73）

三臂，同一 12 条 held-out，同一超参（lr 2e-4、300 步、KL→0.0003 左右）。

| 臂 | 示例里有什么 | 权重 | schema | 回滚 | 缺失填`-` | 补零 | 去重 |
|---|---|---|---|---|---|---|---|
| m71（基准） | 8 条常规 | 均匀 | ✓ | **0/3** | 2/2 | 0/2 | 0/1 |
| `demo` | 8 常规 + **2 回滚** + 2 重复 | 均匀 | ✓ | **3/3** | 2/2 | 0/2 | 0/1 |
| `weight` | 同上 | 值 token ×10（26/457） | ✓ | 3/3 | 2/2 | **0/2** | 0/1 |
| `padonly` | **12/12 全是"只有日期"** | 均匀 | ✓ | 0/3 | 2/2 | **0/2** | 0/1 |

四条读数：

1. **回滚从 0/3 变成 3/3，只是因为加了 2 条演示。** 所以"值级规则蒸不进去"这个说法错了——
   它当时根本没被演示过。**演示是必要的。**
2. **把值 token 加权 10 倍，输出完全没变。** 分数逐项相同，抽查的片段逐字相同。
   **"稀释"这个猜想被排除**：不是梯度质量不够。
3. **补零在 12/12 全是补零的情况下仍然是 0/2**，而且整段输出里 `"00:00"` 出现 **0 次**
   ——训练 KL 已经压到 0.0003。所以**频率也不是原因**。
4. **去重演示了 2 次，仍然 0/1。**

于是剩下的解释只能是"规则的类型"。四条规则按"输出是什么"分：

| 规则 | 触发 | 输出 | 结果 |
|---|---|---|---|
| 缺失 → `-` | 字段不存在 | 固定 token | ✅ |
| 回滚 → `已回滚` | 输入里有"回滚" | 固定 token | ✅（演示后） |
| 补零 | 输入里**没有**时间 | 在复制来的日期后**追加** | ❌（12/12 也不行） |
| 去重 | 两条记录**相同** | **删掉**一条 | ❌ |

猜想（未验证）：**Δ 能装"看到 X 就写 Y"的局部联想，装不了需要"发现缺失"或"跨条目比较"的规则。**
前两条都是"某个 cue 触发一个固定词"；后两条要求模型对输入做变换（追加/删除），
而 Δ 是在权重上加偏置，加偏置可以抬某个 token 的概率，但很难让模型"注意到这里少了个东西"。

**这个解释有一个明显的混淆**：补零同时是"缺失"和"追加"，去重同时是"比较"和"删除"，
四条规则分不开这三者。要分开，需要一个只缺一维的规则（例如"缺时间就填 `-`"——
只测缺失、不测追加）。

**另一条值得记的现象**：训练 KL 0.0003 而测试输出里 `"00:00"` 一次都没出现。
说明这个 Δ 的拟合**高度依赖位置/上下文形状**，不是一条可携带的联想。
这与 §4 里"形状进得来"是一致的：形状（`[` 开头、4 个键）是全局的，值绑不到新输入上。

## 8. 上一节的一半被推翻了：演示的**形状**比规则的**类型**更要紧

上一节说"变换类规则进不来"。两条新读数把这句话改掉了。

**(a) 把演示换成和测试同形（m73 `big`）**：2 条示例，每条 **12 条记录**（3 条只有日期），
与测试 prompt 同形。结果：

| 臂 | 示例形状 | schema | 回滚 | 缺失 | 补零 | 去重 |
|---|---|---|---|---|---|---|
| `padonly` | 每条 1 条记录（12/12 补零） | ✓ | 0/3 | 2/2 | **0/2** | 0/1 |
| `big` | 每条 **12 条记录**（3 条补零） | ✗（多一个 `target_type` 键） | 0/3 | 2/2 | **2/2** | 0/1 |

**同一个规则，在 12/12 演示时进不来，在 3/12 但形状对得上时进来了。** 所以补零的失败不是"变换类进不去"，
而是"演示的形状与测试差太远"——模型在 1 条记录的上下文里学到的东西，搬到 12 条记录的上下文里就失效。
上一节把原因归到"规则类型"，撤回。

**(b) 最简技能：每条回复结尾加「喵」（m75）**

| | 结果 |
|---|---|
| 训练 | 8 条任务，学生看不到规则，教师看到"每条回复最后加一个喵" |
| 训练 KL | 1.14 → **0.0008** |
| 测试（4 条新任务，自由生成） | **4/4 结尾都有「喵」**，且每回复**恰好 1 个**，没有泛滥 |

这条技能没有任何输入条件、没有格式、没有值：**纯"结尾加一个 token"。它进去得干净。**

于是现在能说清边界在哪里（比之前那版窄）：

- **无条件/固定位置的规则**（每句结尾加喵、输出用 JSON 形状）——进得来；
- **"cue → 固定词"的规则**（回滚 → 已回滚，缺失 → `-`）——演示后进得来；
- **要读输入的规则**（补零、去重）——**演示形状必须和测试同形**，否则进不来；
  同形之后补零进来了，去重还没测同形版本。

**结论不再是"Δ 装不了规则"，而是"Δ 能装的规则，强烈依赖演示的形状与覆盖"**——这正是用户说的
"R 那段没有足够展示"。这句话现在有一半的证据，另一半（去重）还没有。

剩下的疑点：

1. `big` 臂 schema 不合法（多输出一个 `target_type` 键）——示例多了、形状变了，**schema 本身也不稳**。
2. 去重（0/1）还没在"同形 + 多次演示"下测过。
3. 代价仍未测。

## 9. 代价：参照系换了之后，"损伤"很小（m76）

上一节把毫不知情的 `R` 当参照。对**always-on** 的技能这是错的参照：`R` 与 `T` 之间的差就是技能本身。
两个参照都算，4 道 new 题（教师强制在同一条序列上）：

| 任务 | KL(T‖RD) | KL(R‖RD) | KL(T‖R) | 复现比 |
|---|---|---|---|---|
| 什么是过拟合 | 0.19 | 0.70 | 1.40 | **86%** |
| 7×8 | **0.01** | 4.62 | 6.53 | **99.8%** |
| 翻译"明天见" | 0.60 | 0.93 | 2.81 | **79%** |
| 什么是缓存命中 | 0.16 | 0.69 | 1.63 | **90%** |

"复现比" = 1 − KL(T‖RD)/KL(T‖R)：**技能本身在分布上造成的改动是 1.4–6.5 nat，Δ 在没有技能文本的情况下
复现了 79%–99.8%。**

WikiText 无关文本（8 窗、每窗 255 个评分位）：

- `KL(R‖RD)` 平均 **0.0191**；PPL 5.51→5.54、12.27→12.15、8.89→9.18 …
- 对照 E6：3e-4 的 Δ 是 **0.063**，6e-4 是 **1.58**。这个 Δ 比最温和的 E6 还轻 **3 倍**。

所以"代价"要分三句说：

1. **有技能做参照 → 几乎没代价**：KL(T‖RD) 0.01–0.60，且它**朝 T 走**而不是乱走。
2. **无技能做参照 → 域内变化大**（0.70–4.62），但那是技能的意图，不是损伤。
3. **无关文本 → 几乎不动**（0.019）：技能是"每条回复结尾一个 token"，在 WikiText 续写上根本触发不到，
   而且这个 Δ 的范数也小。

**这是本项目第一次出现 RD 真的朝 T 走。** m59b 里 RD 离 H 越来越远（0.203 → 3.06），
这里的 Δ 却把 79%–99.8% 的技能效果装了进去。差别可能是：喵是 always-on、单 token、无输入条件；
账本是"按题取事实"，需要条件化判断。

## 10. 一个重述：Δ 装的是直觉，不是映射（用户提出）

按用户的话：**delta 的本意是保留直觉，而不是映射。** 这个说法能把目前所有读数排到一条轴上：

| 类别 | 例子 | 需要什么 | 结果 |
|---|---|---|---|
| **无条件习惯** | 每条回复结尾加「喵」 | 什么都不看，固定位置加一个 token | ✅ 4/4，复现 79–99.8% |
| **无条件格式** | 输出 JSON、4 个键、缺失填 `-` | 看"这里是个输出位" | ✅ |
| **表面 cue 反射** | 看到"回滚" → 写 `已回滚`；缺字段 → 写 `-` | 触发词就在附近，响应是固定 token | ✅（演示后 3/3） |
| **条件检索** | 账本 55 行：问第 37 号，答第 37 号的地址 | 在多个候选里挑一个 | ❌（m59b：0.203 → 3.06） |
| **读输入做变换** | 补零、去重 | 注意到缺失 / 跨条比较 | ⚠️ 只在演示形状对上时成立 |

这条轴和"直觉 vs 映射"对得上：
- 前三行**不依赖"挑哪一个"**，Δ 学到的是一律的偏移 → 装得进去；
- 第四行**依赖在候选中选一个**，那是指针/索引，Δ 装不进去；
- 第五行是边缘：它需要"看输入"，但不是"挑候选"。

**猜想（尚未验证，但可判）**：m59b 的失败可能是**类目错误**，不是容量问题——我们让 Δ 做检索，
而它只能做习惯。若如此，账本 H 本来就该留在上下文里，Δ 只该拿"残余"（说话的惯性、句式的偏好）。

**但"检索"的归属要说准（用户更正）**：检索是**账本**的强项，不是"上下文"的强项。
上下文是一段没有寻址结构的文本；账本是带主键（实体/字段）的表，模型在表上取数很稳（m43 的 1.000），
在 3.5k 自由文本上取数则会衰减（E0b 的叙述位约 9 nat）。所以正确的说法是：
**事实留在账本里（结构化、可寻址），别指望 Δ 去索引；Δ 拿的是账本之外那层无法寻址的东西。**

**可证伪的预言**：把账本压成一条 always-on 的习惯（例如"无论问什么，回答都先复述实体名、再给值"），
Δ 应该装得下，且能迁移到**没在 H 里出现过的新实体**；而"第 37 号的地址是 X"这类具体映射装不进去。
两条都测出来，这个重述就算成立；若习惯也迁移不到新实体，则"直觉"这个词还需要再收窄。
