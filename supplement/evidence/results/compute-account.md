## 2 一遍要多少算力

```
变换器    6 · N · T          = 6 × 9.46e9 × 11,371 = 6.5e14
KL/lm_head 6 · H · V · 位置   = 6 × 4096 × 248,320 × 6,111 = 3.7e13
────────────────────────────────────────────────────
合计（含 12.8 % 填充）                                = 7.8e14
```

| | |
|---|---:|
| 40 % MFU 的理想时间 | **17.2 s / epoch** |
| 实测 | **42–50 s / epoch** |
| 折合 | 15–26 % MFU（好步 500–600 tok/s ≈ 26 %，离群步是换页抖动） |
| 8 遍 / 32 遍合计 | 6.2e15 / 2.5e16 FLOPs |

**时间花在哪**（`bench_kl2.py`，330 个监督位，T=300，B=3）：

| 变体 | s/step | 占 |
|---|---:|---:|
| 前向 + `lm_head`（只算监督位） | 1.55 | 96 % |
| + 反向 KL（fp32） | 1.61 | +4 % |

## 3 复用账

| | |
|---|---|
| 每个监督位被用几次 | **8 次（8 epoch）/ 32 次（32 epoch）** |
| 一个 epoch 的 KL 流量 | 33 GB（1 份 fp16 logits + 2 份 fp16 目标 + 4 份 fp32 活张量） |
| 这些流量的理论时间 | 0.05 s @ 616 GB/s |
| 实测 KL 时间 | **0.06 s** ✔ 与理论一致，所以 KL 不是瓶颈 |
| 新增一个点的成本 | 教师前向 + 打分 ≈ 0.5 s，但价值要重训才能兑现 |

→ **点是极少的，复用的是极高的，而每次复用 96 % 的时间在把 9.46 B 冻结权重再流一遍。**

## 6 结论

1. **KL 不是瓶颈**（0.06 s，占 4 %）。上午"词表是瓶颈"的判断是错的，那是在 mb-pos=1500
   越过显存墙之后测的假象。
2. **真正的约束是一次前向的激活**：约 1.1 GiB / 1,000 token，预算 3 GiB。
3. **内核这条路今天走完了，结果是负的**——见 §6.1。
4. 所以现在的 26 % MFU 是**这套内核下**的合理值，不是实现无能。

### 6.1 内核：能装上，但更慢

三个障碍里两个是环境问题、一个是真障碍：

| 障碍 | 真相 | 结果 |
|---|---|---|
| `causal_conv1d` | 没有 Windows 轮子（只有 CUDA 源码） | 仍走 `F.conv1d` 参考路径 |
| `flash-linear-attention` | PyPI 的 0.6.0 是空壳（`fla` 下只有 `layers`/`models`，没有 `ops`）；GitHub 源码树里有 | 克隆后用 `PYTHONPATH` 指过去，`from fla.ops.gated_delta_rule import chunk_gated_delta_rule` 成功 |
| Triton 初始化 | 不是 sm75 不支持，是 **`PermissionError [WinError 5]` 无法创建 `C:\Users\<user>\.triton`** | 把 `TRITON_CACHE_DIR` 指到工作盘后 driver 正常：`GPUTarget(backend='cuda', arch=75, warp_size=32)` |

装上之后 fallback 警告确实消失了（`chunk_gated_delta_rule` 不再回落），**但更慢**：

| | s/step | tok/s | 峰值 GiB |
|---|---:|---:|---:|
| 参考实现（现状） T=288 bs=8 | 3.70 | **623** | 19.42 |
| fla 内核 T=288 bs=8 | 4.59 | 502 | 19.10 |
| 参考实现 T=576 bs=4 | 3.79 | 608 | 19.02 |
| fla 内核 T=576 bs=4 | 4.45 | 517 | 18.28 |

fla 省了一点显存（-0.3 ~ -0.7 GiB），**慢 20 %**。原因大概是 Triton 在 sm75 + Windows 上生成的
代码质量不如 cuBLAS 的小批量 GEMM，而这个形状（T=288、head_dim=128）本来就小到让 cuBLAS 很舒服。
**所以不用它**：`_fla_src/` 留着当证据，训练脚本不设 `PYTHONPATH`。

→ 那一"4 倍"不存在。要更快只剩"减少权重流量"这一条，而它被显存卡住（§4）。
