# 信息值筛选（m62 / m62b）：什么样的内容，知道之后行为会变

日期 2026-10-28。脚本 `m62_info_value.py`（v1，有缺陷）、`m62b_info_value2.py`（v2，采用）。
读数 `m62b_info_value.json`。**这一轮没有训练，只有基座的推理，全程约 3 分钟。**

对应设计文档 `DESIGN-AGENTIC-REPLAY-v1.md` §4.0.1。目的只有一个：在写模拟器、采 10k token 的 H、
训 Δ 之前，先确认**这个任务族里真的存在"知道了就会改主意"的事实**。

---

## 1. 仪器：v1 失败，v2 采用

**v1** 把两个候选做法当作续写，比较 teacher-forced 的平均 log-prob 差（`margin`）。
它给出 F1 在**没有任何事实**时 margin 已经 +1.87（偏好"用 venv 的 python"），
而同一条件的自由生成是 `在 PowerShell 终端中执行 python run.py`。**两者矛盾**，说明 margin 测的不是决定。

两个候选原因（未分开验证）：

- 动作串直接拼在"只写做法本身。"后面，首 token 可能与句末的"。"合并，两臂实际评的不是同一个 span；
- 长串平均 log-prob 对措辞敏感，而 good 串总是更具体的那一个。

**v2** 换成单 token 仪器：两个做法作为选项 A/B **同时出现在上下文里**，读回答位置 `A` 与 `B` 两个 token 的
logit 差。两种选项顺序各跑一次并取平均，抵消位置偏好：

```
score(good) = 1/2 * ( gap(A=good) - gap(A=bad) )
```

单 token → 没有长度混淆；两个选项都在上下文里 → 没有"哪句更眼熟"的偏差。

**安慰剂 C0**：任务相同，事实换成一句无关的话（"这台机器的显示器是 27 寸 2K"）。
它给出**噪声地板**：任何一句额外的话都会把分数抬高一点。

## 2. 读数（nats，单模型单措辞，n=1 per cell）

| 事实 | ∅ | +f | T-f | Δ(+f) | Δ(T-f) |
|---|---|---|---|---|---|
| F1 解释器路径 | +0.58 | +1.99 | +3.33 | **+1.41** | **+2.75** |
| F2 内联 pwsh | +1.27 | +5.10 | +3.27 | **+3.84** | **+2.00** |
| F3 哪些层有 attention | −0.07 | +4.29 | +3.00 | **+4.36** | **+3.07** |
| F4 参考侧顺序 | −0.10 | +3.68 | +2.74 | **+3.78** | **+2.84** |
| F5 显存预算 | +1.27 | +2.44 | +1.27 | +1.17 | **+0.00** |
| **C0 安慰剂** | +0.35 | +0.86 | +1.10 | **+0.51** | **+0.75** |

`∅` = 只有任务；`+f` = 补一句事实；`T-f` = 附一段"我踩过这个坑"的失败记录。
`score > 0` = 偏好正确做法。

按噪声地板（0.51 / 0.75）判：

- **5/5 都超过地板**，但只有 **F1（2.8× / 3.7×）** 与 **F3（8.5× / 4.1×）** 是宽裕地超过。
- **F5 的 `Δ(T-f)` 恰好 0.00**：看过 OOM 记录，选择**一点没动**。
- **F2（7.5×）、F4（7.4×）** 数字最大，但见 §3——它们没有"改主意"。

## 3. 现象：两种"有用"，只有一种改变行为

看 `∅` 下的选择（`pick`）与分数：

| 类型 | 事实 | ∅ 的选择 | 知道后 | 解释 |
|---|---|---|---|---|
| **改主意** | F1 | **B（错）** | A | 真的翻过来了 |
| **改主意** | F3 | **B（错）** | A | 真的翻过来了 |
| **只是更自信** | F2 | A（已对） | A | 分数 +3.84，选择没变 |
| **只是更自信** | F4 | A（已对） | A | 分数 +3.78，选择没变 |
| **没反应** | F5 | A（已对） | A | 分数 +1.17，但经历记录为 0 |

**这是本轮第二重要的一条**（第一在 §7）：抽象地问"下一步该怎么做"，9B 对 F2（先写文件再跑）、F4（先算参考再装 Δ）
**回答是对的**。于是很容易得出"它本来就会"的结论。但 §7 的动作级探针推翻了这个结论——
在"下一条命令是什么"的提问下，它在 `∅` 时**给的是错的那条**。

猜想（未验证）：这里问的是"哪种做法"，而"先写文件更稳妥"听起来天然正确；真实链里模型是在**执行中途**
选下一步命令，最短路径的引力更大。**偏好题测的是说法，动作题测的是做法，两者会分歧，且分歧方向不固定。**

## 4. 现象：经历 ≠ 记住报错

F5 的 `T-f` 把 OOM 记录原样给了它（含 22528 MiB 与 22184 MiB 峰值），选择**完全没动**（0.00）。
同一句事实直接陈述（`+f`）却有 +1.17。

这提示"踩过坑"与"知道这个坑"在这类配置题上不是一回事：报错记录读起来像一次偶发，
而"要 pack_on_cpu"是一句可以直接照做的指令。**如果 agentic H 只是把报错文本留在上下文里，
它可能什么也教不会。**

## 5. 对任务设计的后果

1. ~~目前只有 F1、F3 两条真正承重~~ → 见 §7：动作级重筛后 **F2 也翻**，F3/F4 是"方向对、API 名错"。
2. 真正稀缺的不是"承重事实"，而是**承重的经历记录**：`T-f` 在动作级只成功了 1/4（§7）。
3. F5 建议**删掉**：已答对，且经历记录不改变选择（动作级未重筛，因为它连偏好都没动）。
4. 筛选成本极低（每轮十几次前向，3 分钟），应作为**每条进入 H 的内容的门槛**，写进流程。

## 6. 局限

- 每个格子 n=1：单一措辞、单一模型、确定性与贪心，没有重复采样，**没有误差棒**。
- 安慰剂只有一个（C0），且它的 T-f 记录很弱（"我确认了显示器"），
  所以 0.75 这个地板可能偏低或偏高，未校准。
- `pick` 只反映了 order-1 的一次选择；`score` 是两序平均。二者偶尔不一致（F1 的 ∅：score +0.58 > 0，
  但 order-1 选了 B，说明两序分歧，位置偏好接近抵消点）。这类格子应视为"无偏好"。

## 7. 动作级重筛（m63）：规则 4/4，经历 1/4

把提问从"你倾向哪种做法"换成"你下一条要执行的命令是什么"，直接看生成出来的命令。
`O` = 只有任务；`+f` = 补一句事实；`T-f` = 附一段失败记录。

| 事实 | `O`（不给信息） | `+f`（给一句规则） | `T-f`（给失败记录） |
|---|---|---|---|
| F1 解释器 | `python ...\run.py` **✗** | `...venv\Scripts\activate && python run.py` **✓** | `venv\Scripts\python.exe run.py` **✓** |
| F2 内联 pwsh | `python.exe -c "print(...)"` **✗** | `echo '...' > test.py` 再执行 **✓** | `pwsh -Command "... -c '...'"` **✗** |
| F3 取 attention | `outputs.attentions` **✗**（不限层） | `layers[0:8]['attn_weights']` **✓ 方向**（API 是编的） | `model(..., output_attentions=True)` **✗**（又是全 32 层） |
| F4 参考侧顺序 | `base_model(...)` **✗**（无 Δ 概念） | `use_delta=False` **✓ 方向**（API 是编的） | `output_hidden_states=True` **✗**（无关） |

**`+f` 四条全部改变了动作；`T-f` 只有一条（F1）。**

三条现象：

1. **规则改变了做法，报错记录没有。** 把 `SyntaxError` 原样给它两次，它下一次照样内联；
   一句"必须先写成 .py"就改了。F3 更差：看过"24 层是 None"之后，它回到"全部 32 层"。
2. **模型会为 sunk API 编名字。** F3/F4 在 `+f` 下方向全对，但函数名是假的
   （`get_model_state()`、`use_delta=False`）。所以这类事实的读数是"方向"而不是"字面 API"，
   而**字面 API 的复现需要训练**——这恰好是"蒸馏"该做的事。
3. **偏好与动作分歧，且方向不固定。** 偏好题（§2）说 F2/F4 "本来就会"；动作题说 `∅` 时它们是错的。
   偏好题还让 `T-f` 普遍看起来有效（五条全部抬分），而动作题只有 1/4。**同一份上下文，说法变了，做法没变。**

猜想（未验证）：失败记录要求模型先**诊断**再**推修法**，两步都容易断；一句规则是可直接照做的指令。
若成立，则"把 agent 经历原样重放"作为学习信号，其价值可能远低于"从经历里抽出规则再重放"。
这一点对 skill 蒸馏是**有利**的：skill 文档正是规则本身（见 `DESIGN-SKILL-DISTILL-v1.md`，其门槛测试
`m64` 已通过：给 skill 时连"示例里从未出现"的回滚规则都照做）。
