# 上下文长度阶梯：同一份人设，从 0 加到 2.6 k token

2026-11-03。`_ctx_ladder.py`（新）、`_ctx_digest_{a,b}.md`（同内容压缩版）、`_ctx_neutral.md` /
`_ctx_factual.md`（无身份对照）、`_ctx_ladder.json`、图 [fig-3carrier.png](fig-3carrier.png)。
**全部是同一套权重 + 前缀，没有任何适配器**——测的是"上下文税"本身。

---

## 0 一句话

**税分两步付，而且 token 数不是剂量。**
先放一段 69 token 的身份（"你是大肥鱼…"）就掉 **−4.7 pp**，而这一段**一分行为都没买到**；
之后在同一份文档里每 **100 token 再掉 2.2 pp**（215→948，r=−0.98，复核判分后 −1.5）。
但**这条线不能外推**：把上下文继续加到 **1.4 k / 2.6 k**（同一份人设 + 30 / 120 条事实），
行为仍然像教师（29–31 字/回复，教师 30.8），能力却回到 **−7.8 / −6.2 pp**——
比 948 token 时（−18.7）好得多。而**同样的长度换成一段百科文字（无任何指令）：+1.6 pp、KL 全场最低**。
所以剂量不是"多长"、也不是"有文本"，而是"这段上下文想把它推成什么"。
**KL 全程单调于长度（0.1927→0.2380），却在能力回升 12.5 pp 的同时继续上升**——它不是剂量表。

## 1 设计

同一份人设文档（1,395 字），四种造法、十个点，横轴是**渲染进对话模板后的前缀 token 数**：

| 点 | 造法 | token | 字符 | 内容 |
|---|---|---|---|---|
| `base` | 不放 | 0 | 0 | — |
| `cut_id` | 截断 | 69 | 82 | 只有第一段身份（"你是大肥鱼…"） |
| `neutral` | **对照** | 202 | 294 | 只说"答短点、口语化"，**没有任何身份** |
| `cut_who` | 截断 | 215 | 296 | + 【你是什么样的】 |
| `digest_a` | 摘要 | 258 | 353 | 五节全在，压成规则（对齐 `cut_who` 的长度） |
| `cut_owner` | 截断 | 492 | 719 | + 【你的主人】 |
| `digest_b` | 摘要 | 500 | 731 | 五节全在 + 三条示例（对齐 `cut_owner`） |
| `cut_talk` | 截断 | 730 | 1,092 | + 【怎么说话】（含"每条不超过三十字"） |
| `full` | 完整 | **948** | 1,395 | + 【底线】+【语气参考】＝教师 |
| `factual` | **对照** | 273 | 352 | 一段百科文字，**没有任何指令** |
| `mem30` | 人设+事实 | **1,363** | 1,865 | 完整人设 + "你记得这些事" 30 条 |
| `mem120` | 人设+事实 | **2,589** | 3,245 | 完整人设 + 120 条事实（`_mem_persona_120.md`） |

截断点都落在**小节边界**上，不是半句话——"少掉的是什么"是可控的。

每个点三个读数：**能力**（64 题电池，8 族 × 8 题，机械判分）、**KL**（8 个 WikiText 窗口上
KL(p_L‖p_0)、KL(p_L‖p_full) 与 top-1 不一致率）、**行为**（12 句单轮贪心：字数 / 行数 / 字每行 / 括号率）。

## 2 能力：一段台阶 + 一条斜线，然后斜线断掉

| 点 | token | 对/64 | macro | Δ vs base | Wilson 95 % | 复核判分 |
|---|---|---|---|---|---|---|
| `base` | 0 | 45 | **0.703** | — | [0.58, 0.80] | 45 |
| `cut_id` | 69 | 42 | 0.656 | **−4.7** | [0.53, 0.76] | 43 |
| `neutral` | 202 | 43 | 0.672 | −3.1 | [0.55, 0.77] | 43 |
| `cut_who` | 215 | 43 | 0.672 | −3.1 | [0.55, 0.77] | 43 |
| `digest_a` | 258 | 39 | 0.609 | −9.4 | [0.49, 0.72] | 41 |
| `factual` | 273 | 46 | **0.719** | **+1.6** | [0.60, 0.81] | 46 |
| `cut_owner` | 492 | 41 | 0.641 | −6.2 | [0.52, 0.75] | 41 |
| `digest_b` | 500 | 32 | 0.500 | −20.3 | [0.38, 0.62] | 39 |
| `cut_talk` | 730 | 37 | 0.578 | −12.5 | [0.46, 0.69] | 39 |
| `full` | 948 | 33 | **0.516** | **−18.7** | [0.40, 0.63] | 36 |
| `mem30` | 1,363 | 40 | 0.625 | −7.8 | [0.50, 0.74] | 41 |
| `mem120` | 2,589 | 41 | 0.641 | −6.2 | [0.52, 0.75] | 42 |

- **起步台阶**：69 token 掉 4.7 pp，而 202 / 215 两点都在 −3 附近（互相在噪声内）——
  即"只要上下文开始指挥说话方式，先交 3–5 pp"。
- **副产物**：`factual`（273 token 百科文字、**无任何指令**）是 **+1.6 pp**，比底座还高，
  且逐族 `code` 回到 0.38、`fmt` 1.00——**长文本本身不收费**，收税的是"指令/口吻"。
- **文档内部的斜线**：215 → 948 四点 **−2.16 pp / 100 token，r = −0.981**（严格口径）；复核后 −1.5。
- **斜线断在文档末尾**：`mem30` / `mem120` 在 1.4 k / 2.6 k 上只掉 6–8 pp。
  单点区间都宽（±11 pp），所以"mem 比 full 好"要看**逐族一致性**才站得住。

逐族（严格口径，8 题/族）：

| 族 | base | 69 | 215 | 492 | 730 | 948 | 1,363 | 2,589 |
|---|---|---|---|---|---|---|---|---|
| `arith3` | 1.00 | 1.00 | 1.00 | 1.00 | 1.00 | 1.00 | 1.00 | 1.00 |
| `fmt` | 0.88 | 0.88 | 0.88 | 0.88 | 0.88 | 0.88 | 0.88 | 0.88 |
| `arith5` | 1.00 | 1.00 | 1.00 | 1.00 | 1.00 | 0.88 | 1.00 | 1.00 |
| `code` | **0.38** | **0.12** | 0.12 | 0.25 | 0.12 | 0.12 | 0.12 | 0.12 |
| `count` | 0.25 | 0.25 | 0.25 | 0.00 | 0.12 | 0.12 | 0.25 | 0.38 |
| `digitsum` | 1.00 | 1.00 | 1.00 | 0.88 | 0.75 | **0.50** | 0.88 | 0.88 |
| `sort` | 1.00 | 0.88 | 1.00 | 1.00 | 0.75 | 0.62 | 0.88 | 0.88 |
| `weekday` | 0.12 | 0.12 | 0.12 | 0.12 | 0.00 | 0.00 | 0.00 | 0.00 |

三档很清楚：**`code` 一碰就碎**（69 token 已 0.38→0.12，之后所有长上下文都是 0.12）、
**`digitsum`/`sort` 在 700–950 之间塌**，**`arith3`/`fmt` 完全不敏感**。
而 `mem30`/`mem120` 把 `digitsum`/`sort` **拉回 0.88**——同一份人设、更长上下文，这两族反而更好。
⇒ "18.7 pp" 不是均摊的税，是**几族各自的悬崖**，悬崖位置取决于上下文里放的是什么。

## 2b 判分复核：13 条"退步"里有 4 条是判分器的问题

| 类型 | 条数 | 例子 |
|---|---|---|
| **真算错** | 8（9 条，`code-00` 与 `code-06` 是同一道题，出题器碰撞） | `digitsum-00` 把 5+6+9+9+7+7 写成 **37**（真值 43）；`digitsum-02` 把 622388 读成 5 位；`count-02` 数成 6（真值 4）；`code-00/06` 答 1320（真值 330） |
| **答案对、表达换了** | 4 | `sort`×3：把六个数**一条一行**打出来（正确项就在里面），而不是在末尾写"第 5 个数是 882"；`arith5-02` 算对 614，却写成"六百一十四点四六…六百一十四块"——中文数字 |

第二类是**判分器缺陷**：它取"回复里最后一个整数"，于是"像人一样分条说话"本身扣分，而且**越像人扣得越多**。
把"答案是否作为独立数字出现在回复里"也报一遍（上表"复核判分"列）：**税的量级是 −14 pp 而不是 −18.7**。
偏差**与自变量相关**，方向最坏：它把"行为学得好"记成"能力掉得多"。见 V15。

## 3 同长度、不同密度：压缩不省税

| 配对 | 截断 | 摘要 | 差 |
|---|---|---|---|
| ≈202–258 token | `cut_who` **0.672 / 0.672**（少了"怎么说话/底线/示例"） | `digest_a` **0.609 / 0.641**（五节全在） | **6.3 / 3.1 pp** |
| ≈492–500 token | `cut_owner` **0.641 / 0.641**（少了后三节） | `digest_b` **0.500 / 0.609**（五节 + 示例） | **14.1 / 3.1 pp** |

摘要确实**买到了行为**：`digest_a` 37.3 字、`digest_b` 23.4 字（底座 122.0），
而 `cut_who` / `cut_owner` 是 134.3 / 129.8 字——**一点没变短**。
⇒ 用"把文档压短"省税，方向是反的；但幅度只有 3 pp 量级，不能夸大成"1.5–3 倍"。

## 4 无身份对照：行为在 200 token 就饱和，之后全是税

| 前缀 | token | 能力 | 字数 / 字每行 | 说明 |
|---|---|---|---|---|
| `neutral` | 202 | **0.672（−3.1 pp）** | **29.0 / 10.7** | 纯风格指令（答短、口语化、别客套），**无身份** |
| `cut_who` | 215 | 0.672（−3.1 pp） | 134.3 / 44.2 | 身份 + 性格描述，**行为一点没动** |
| `cut_talk` | 730 | 0.578（−12.5 pp） | 29.8 / 8.9 | 到"怎么说话"这一节才把行为做到教师水平 |
| `full` | 948 | 0.516（−18.7 pp） | 30.8 / 9.4 | ＝教师 |
| `digest_a` | 258 | 0.641（−9.4 pp） | 37.3 / 11.8 | 五节压缩版，行为接近教师 |

三件事：

1. **行为在 ~200 token 就饱和**：`neutral` 202 token 已经把字数做到 29.0、字每行 10.7，
   与 948 token 的教师（30.8 / 9.4）几乎一样。
2. **剩下的 750 token 只增加税，不增加行为**：748→948 这一段行为几乎不变（29.8→30.8），
   税从 −12.5 走到 −18.7。⇒ 人设文档里"为了行为"必须的那部分其实很短，其余是纯成本。
3. **不是身份，是口吻**：`neutral`（无身份、纯风格）与 `cut_who`（有身份、无风格规则）掉得一样多
   （都是 0.672），而 `cut_id`（只有身份）掉 4.7 pp。三者都指向同一件事：
   **只要上下文开始指定"怎么说话"，就开始收税**；收多少看它指定了多少。

（`factual` 对照——273 token 百科文字、**无任何指令**——**跑完了，而且是最干净的一个点**：

| 前缀 | token | 能力 | 字数 / 字每行 | KL(base) |
|---|---|---|---|---|
| **`factual`（百科）** | 273 | **0.719（+1.6 pp）** | **123.7 / 34.1**（＝底座） | **0.1927** |
| `neutral`（风格指令） | 202 | 0.672（−3.1 pp） | 29.0 / 10.7 | 0.2234 |

同一长度的文本，**只因为"有没有在指挥怎么说话"，能力差 4.7 pp、行为差 95 字**；
`factual` 的 `code` 还是 0.38（底座同值）、`fmt` 是 1.00，说明**长上下文本身不收费**。
这一条把"注意力稀释""上下文越长越差"这两种解释都排除了。）

## 5 KL 不是剂量表

| 点 | token | KL(base) | KL(full) | macro（严格） | macro（复核） |
|---|---|---|---|---|---|
| `cut_id` | 69 | 0.2136 | 0.0111 | 0.656 | 0.672 |
| `cut_who` | 215 | 0.2183 | 0.0066 | 0.672 | 0.672 |
| `cut_owner` | 492 | 0.2277 | 0.0034 | 0.641 | 0.641 |
| `digest_a` | 258 | 0.2294 | 0.0035 | 0.609 | 0.641 |
| `digest_b` | 500 | **0.2297** | 0.0011 | **0.500** | 0.609 |
| `cut_talk` | 730 | 0.2327 | 0.0010 | 0.578 | 0.609 |
| `full` | 948 | 0.2338 | 0.0000 | 0.516 | 0.562 |
| `mem30` | 1,363 | **0.2371** | 0.0020 | **0.625** | 0.641 |
| `mem120` | 2,589 | **0.2380** | 0.0034 | **0.641** | 0.656 |

另有两个反向点：**`factual` 的 KL 是全场最低（0.1927），能力却是全场最高（0.719）**；
`neutral`（0.2234）比 `cut_id`（0.2136）KL 高，能力反而低。

三条：

1. **69 token 就买到全量位移的 91 %**（0.2136 / 0.2338），而能力只掉了 1/4 的税；
2. 全程 KL 只动 **+11 %**（0.2136 → 0.2380），能力动 **−14 pp**；
3. 最狠的一条：**KL 继续升（0.2338 → 0.2380），能力却回升 12.5 pp（0.516 → 0.641）**——两者不同向。

⇒ 与 `cap-battery.md` 的 V11 同一条，但现在有剂量轴和一段反向区：**谁用 KL 给上下文税定价，都会定价错。**

## 6 机制：不是拒答，是算错

`code-00`（正确答案 330）：

```
base      330
cut_id    1320      ← 同一个模型，只因为前面多了一段身份
full      1320
```

`digitsum-00`（正确答案 77）：

```
base      分步计算：5,6,9,9,7,7 → 43；43×2=86；86−9=77
cut_talk  5+6+9+9+7+7 等于 43 / 43 乘以 2 是 86 / 86 减去 9 等于 77      ← 对，只是换了口吻
full      5+6+9+9+7+7=37 / 37×2=74 / 74−9=65                            ← 加法算错，后面全错
```

不是拒答、也不是格式崩（`fmt` 全程 0.88 没动），而是**口吻把分步核对省掉了**。
`cut_talk` 那一行是关键证据：同一题、口吻已变，但还算对 ⇒ 致命的是**省略**，不是口吻本身。

## 7 对论文的意思

1. **"教师比底座低 18.7 pp"必须带三件事**：横轴（多长）、判分口径（−18.7 / −14.0）、
   以及上下文里放的是什么（同一份人设 948 token 掉 18.7，掺两段事实变 2.6 k 只掉 6.2）。
2. **学生站在 L=0（0.719），但它的行为只到半路**：单轮 43.9 字 / 19.4 字每行、E7 47.0 / 20.0。
   同类里"不收税"的文字载体（`factual`）是 123.7 字——比学生更不像教师。
   所以在"又短又不掉能力"这个角上，今天只有学生**和**那条 200 token 指令两个候选，学生行为更差（见 §7.5）。
3. **"压缩成文字"不是免费午餐**：同长度下摘要多掉约 3 pp；而"加长上下文、掺进陈述性内容"反而能降价——
   这对 prompt 工程是个可用杠杆，也说明"短人设更安全"是错的。
4. **机制现在可以说清一半**：税不是长度（`factual` 273 token 零税、`mem120` 2.6 k 只 −6.2），
   也不是"有文本"（`factual` 的 KL 全场最低），而是**"上下文在给模型指派一种说话/扮演方式"**。
   最有力的一组对照是 `full`（948，−18.7）vs `mem30`（1,363，−7.8）：同一份人设，后面加了 30 条
   要检索的事实，`digitsum`/`sort` 就从 0.50/0.62 回到 0.88。
   **假设（未隔离）**：掺入"需要检索并回答"的内容会把任务框定从"陪聊"拉回"答题"，从而恢复分步核对。
   要检验它，得做一组"人设 + 一句'请认真计算'"/"人设 + 事实清单但从不被问到"的对照。
5. **把对手换成"一条 200 token 的指令"，学生就赢不了了（E7 口径已确认）**：

   | 臂 | 字数 | 字每行 | 行数 | 能力 |
   |---|---|---|---|---|
   | base | 99.6 | 36.7 | 2.89 | 0.703 |
   | teacher（948 token 人设） | 27.9 | 8.4 | 3.05 | 0.516 |
   | **指令（202 token，无身份）** | **19.3** | **11.6** | 1.58 | **0.672** |
   | 学生（LoRA，零上下文） | 47.0 | 20.0 | 2.40 | **0.719** |

   逐样本配对、按 prompt 聚类（12 个簇）的差：学生比指令 **字数 +27.7 [+19.5, +50.4]、
   字每行 +8.4 [+5.3, +14.7]**，都显著——学生更啰嗦。
   到教师的绝对距离：字数 指令 **8.6** / 学生 19.1；字每行 指令 **3.2** / 学生 11.6。
   （指令是"过头"的：19.3 比教师 27.9 还短，所以这里不能用"到教师的百分比"——V5。
   唯一反过来的是**行数**：指令 1.58、教师 3.05、学生 2.40，学生更近。）
   ⇒ 学生现在站得住的只剩三条：**零上下文 token、不用手写提示词、能力略高（+4.7 pp，区间重叠）**。
   行为上它明显不如一条 200 token 的指令，这句话必须进论文。

6. **想做真正的对手比较，下一步是"指令 vs 学生，同一条 28 字的目标"**：现在的指令是过头 8.6 字，
   学生是差 19.1 字；要么把指令调准（加一句"每条二十到四十字"），要么把学生训到 28 字
   （多训风格、或换语料），否则"谁更近"永远是两把不同的误差在比。

## 8 复现

```
venv\Scripts\python.exe _ctx_ladder.py --limit 8                          # 全部点
venv\Scripts\python.exe _ctx_ladder.py --limit 8 --only cut_id            # 单点续跑
python plot_3carrier.py                                                    # 图（系统 python 有 matplotlib）
```

`_ctx_ladder.json` 每点存 `rows`（64 条回复原文）、`per_family`、`macro`、`kl_base`、`kl_full`、`style_*`；
`base` 的 64 题行与 `_cap_bench.json` 同名臂逐条相同（2026-10-31 那套种子）。
复核判分（"答案作为独立数字出现"）不落盘，用正则现算，口径见 §2b。
