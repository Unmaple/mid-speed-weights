# 简版：让LLM 学会睡觉

> **摘要（虽然本文件已经是摘要了）**：agent 每到一个窗口边界就 compact 一次，把这段经历压成一张便条，交给下一个自己。它有"交接"，也有便条，但没有"巩固"——而把经历写进权重的那个动作，人类是在睡眠里完成的。

---

## 1. 缺跨 compact 周期的载体

**"跨 compact"这一档已经在做，但借的是快权重的位置，和代价**：摘要 + 滑窗就是它，生命周期与我们要做的东西**是同一个**。缺的是这一档的**载体**——它只能用 token，而 token 有两笔硬账。

| 档 | 载体 | 生命周期 | 现状 |
|---|---|---|---|
| 快 | KV cache | 一次会话 | 有 |
| **中** | **摘要 + 滑窗** | **跨 compact** | **有，但被 token 信息熵和膨胀率卡住————也就是付快权重的代价，购买跨compact的记忆** |
| **中** | **参数 Δ（本方案）** | **跨 compact** | **缺** |
| 慢 | 冻结权重 | 永久 | 有 |

**第一笔是膨胀率。** KV 是快权重，代价是压缩率差：一个 token 进 KV 要占几十 KiB（本项目 64 KiB/token）。**"存下来"这个动作本身把 token 放大三到四个数量级**——300KB信息熵的 token 即便用 DeepSeek-V4.1-Flash 那一档的跨层复用与低精度 KV，也是**接近1个 GB** 常驻。对于当前测试的qwen3.8-27B，这个数字将会是48.8GiB.

**第二笔是它随上下文线性长。** 这段被保留的历史，之后每一次请求都要重新 attend，显存随上下文 **O(L)** 涨——它不是"放在那里不动"的存储。

**综上，token方法的局限是信息量。** token 能装的信息有上限（§2 那个熵，soft token一定程度解决，并非无人优化）。所以"多留一点"和"多写一点"都不是出路：**存得越多，膨胀与 attend 成本同步上涨，信息量只按 token 数线性增长。**

结论：要做的不是造一个新时标，是**给已经存在的这一档换一个不膨胀的载体**——参数。

## 2. 天花板：为什么"把摘要写得更好"没有出路

用熵来量（量级估计，不可相互换算）：

| | 信息熵 |
|---|---|
| 1M 上下文 | ~300–375 KB |
| 一次 compact 之后存活（≤8k 摘要 + 155k 滑窗 ≈ 163k token） | **~61 KB** |
| 人类一生的长期记忆 | ~125 MB |

差三个数量级，**而且这个差不会随会话变长而缩小**：每次 compact 都压回同样的预算，所以第 100 次 compact 之后，能带过切点的还是那么多。**容量由窗口宽度 W 和摘要上限 cap 决定，加钱买不到。**

所以问题不是"摘要写得不够好"，是**通道太窄**。这解释了为什么所有"更聪明的压缩"都只能在这个盒子里优化。

## 3. 睡眠：人类有这一步，LLM 没有

人类：近期的事还醒着（工作记忆），旧的在睡眠里被重放、被写进皮层。醒来还是同一个人。

dsh：滑窗就是"还醒着"的那部分——但它**逐字占着 KV**；摘要是一张便条——**有损、占 token、且不随会话累积**。缺的正是中间那一步：**把经历写成参数**。

takeaway：**它不是给未来的自己写笔记，它是把笔记本交给另一个人。**

## 4. 做梦：巩固的机制是生成式重放

要在 compact 边界上做那次写入，需要"训练材料"。来源是**教师在完整历史的上下文处进行输出采样**：生成问题、再生成答案。四项性质与梦对得上——内容**内部生成**、以**近期经验为条件**、**离线**、**直接用于改写权重**。

**它更像 REM 的梦，而不是 NREM 的重放（也有人做）**：海马重放是复现觉醒序列，而我们的 probe 是"想一个用户接下来可能会问什么"——**构造，不是录像**。

**需要注意：训练材料并不全是模型自己生成的。** H 里绝大部分是**外部输入**——用户消息、工具返回、文件、命令输出、报错。模型只负责"问什么"，答案是它对着这些外部材料**有据地**采样出来的。**如果 H 全是自生成内容，这套做法就退化成已知的模型自噬（model collapse）**：一代比一代窄，最后塌掉。它这里不塌，是因为每次"做梦"都被外部事实钉住。

所以这一步该选"重放"还是"自蒸馏"？**倾向自蒸馏**，三条理由：

1. **生成不修改生成者**——教师冻结，写的人与被写的东西是两个系统，因此不会像"训练在自身输出上"那样逐代坍缩；
2. **人不会把过去一天重新度过一遍**——重演是存在的，但自蒸馏同样可以承担重演，而且能覆盖重演覆盖不到的那部分；
3. **学生要在没见过的问句上被测**，所以训练分布该是"可能被问什么"的**预测分布**，而不是"过去问过什么"的**经验分布**——重放只覆盖后者。

代价：**梦会编，编的会被巩固**。所以 probe 的"接地率"（能否在历史里找到支撑）是必测项，不是数据清洗细节。但这本质是教师在长上下文发生能力退化，这并不是我们这个compact足以解决的问题，这需要预训练侧和后训练侧处理。

## 5. 核心方案：中速权重

> 在 compact 边界上，用一次真实梯度，把"完整历史 H 与保留尾部 R 的落差"写进一个 ≈40 MB、会话局部、可旁路、永不合并的 Δ。

两条判据决定了它该长什么样（编号沿用完整版 §2.5）：

- **A 写点 = compact 边界**。不在边界上写，写的就不是"被丢掉的那部分"，而是在复刻 KV 还握着的内容——那是抢快权重的活。
- **B 载体 = 参数**。只要还是 token（摘要、soft token、账本注入），成本就随长度 O(n)；参数的附加成本不随历史长度增长。
- **D 生命周期 = session 局部、可清除**（`Δ=0` 逐位回原）。否则它是慢权重，不是中速权重。

（**C 是监督方式**：用完整历史教师的全词表 KL——这不是我们的创新，context distillation 的标准做法即此，Doc-to-LoRA 的 Eq. 2/4 就是它。所以真正属于我们的是 **A + B + D 的组合**。）

## 6. 验证：五个可证伪的预测

| | 预测 | 若不成立 |
|---|---|---|
| **P1** | Δ 在未见问题上优于实际 compact 输出 | 转成本主张；无成本优势则停 |
| **P2** | 等参数下多层薄 Δ 优于单层厚 Δ | "快慢交错"的类比不成立 |
| **P3** | 清空 Δ 后回到 baseline；换历史不迁移 | 无法隔离，不能上产品 |
| **P4** | 容量翻倍有可测增益且不饱和 | 40 MB 已过量，应缩小 |
| **P5** | 文本强在"说得清"，Δ 强在"做得到" | 两条通道无分工，价值主张弱 |

四臂：`R`（只留尾）、`RD`（尾+Δ）、`SR`（摘要+尾）、`SRD`（摘要+尾+Δ）。主判据是配对 KL 的相对降幅与它的 CI。
## 7. 已有一轮预实验（含 10-25 晚更新）

三份 ~7k 加一份 20k 合成历史，每份 64 道固定测试题；主实验四臂（T/R/RD/SR/SRD），20k 那轮扩到六臂（S1/S2 两档摘要）。单卡 27B、固定 64 次更新、冻结基座、Δ 独立保存不合并。**原始数据在完整版 §11（预实验）与 §12（新增证据）**，此处仅有结论。

**已经说明**：Δ 确实能把一部分历史效应写进参数——R→RD 相对下降 H1 25.1%、H3 27.9%、H20 28.5%（CI 均不含零），H2 只有 7.6%（跨零）；叠加摘要后 H3 仍有 17.8%、H20 的 S2 侧 10.7%。无关 32 题上 Δ 的平均漂移 0.004–0.026，与“加一段摘要”同量级、部分更小；三对 greedy 全维持 31/32。

**同时也收紧了三件事**（详见完整版 §12）：① **它不承载可复述内容**——教师参照的摘要复现只有 −5.6 / −6.7 / +3.5%（H20-S1/S2、H3），而答案通道是 25–28%；② **收益不全是历史特异**——H1 拿 Δ(H2) 为 −13.8%，但 H2 拿 Δ(H1) 为 +9.8%；③ **容量不是瓶颈，监督才是**——有效秩只有 2–3（名义 64），训练侧监督上界约 700 bit，而 64 题的 gap 中位数仅 0.074、top-10 题占 65%、12/64 题几乎没有历史依赖。

**尚未说明**：H2 的效应仍接近零；三条历史都很短（~7k），摘要几乎没受压；20k 上两档摘要正文只差 152 token，**不是严格的容量对照**。**所以现在仍不能说 Δ 优于文本摘要**——在 r≈4 时文本的每字节密度高约四个数量级。

**一个信号**：在 20k 历史上，1k 的摘要预算已经打不满（连续两次被截断），2k 才正常结束。这是"通道太窄"的第一次实测，比任何 KL 都直接；同类现象在更长的摘要请求上也反复出现（之前部分任务需求下，观察到27B 写 16k 摘要会超限，qwen3.8max也遇到过）。

**而这里有一道与压缩预算无关的墙**：1M 窗口最多承载约 **375 KB** 的信息熵。所以**无论把摘要预算放到多大**，一次 compact 能带过去的经验上限就是 375 KB——放开预算只是在逼近它，不能越过它。（当前参数下实际交付约 61 KB，那是dsh默认配置。）

对 agent 而言后果很直接：**经验一旦超过 375 KB，就再也无法完整交给下一任自己**。这不是实现问题，是这一代架构的容量问题。

## 9. Full Takeaway

> 现有 compact 在有限文本预算下，会丢掉影响后续行为的历史信息。我们检验：在边界处，把这些效应写进一个可清除的局部 Δ，能否改善未见问题上的表现，并取得可接受的成本。

如果它成立，那这一步就是 **agent 学会睡觉**——梦是它自己做的。
