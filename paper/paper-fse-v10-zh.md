## 摘要

在长程会话中，历史反复越过压缩边界，而存活下来的只有文本：一份摘要、一个滑动窗口，或一本台账。三者都按每次使用计费：在缓存稠密注意力下，一段被携带的 $k$ 个 token 的前缀，在每个解码位置上增加 $O(k)$ 的注意力计算，在 $m$ 个解码位置上共 $O(km)$；而固定 adapter 在每个位置上只增加一个常数，且不占任何上下文位置。三者还都有上限——摘要最多 32k token，滑动窗口宽度固定——因此一次压缩后存活的东西是一个常数，与它之前有多少历史无关，而它的**容量**、不只是它重复发生的价格，才是天花板。我们问的是：这个载体能否改为参数——在压缩边界处，我们把全上下文教师的输出分布写进一个会话局部的、未合并的低秩 $\Delta$，它在被清除时逐位相同，并把它与一个**真实的**压缩引擎的输出相比，后者的摘要预算在 $16\times$ 的范围内被扫描，而 $\Delta$ 的成本保持固定。在单个 27B 模型、四段历史上，$\Delta$ 相对仅尾段基线把与教师的散度降低 25.1/28.0/28.5%（第四段历史为 7.7%，区间跨零），在一段历史上于摘要之上再降 17.8%；在一段 20k token 的历史上，文本载体一直更好，直到摘要被压到 128–256 token——历史的 77.5–154.9$\times$ 压缩——比较在那里反转；而在不相关问题上，$\Delta$ 的代价是 0.026 nats/位置，加一个摘要则是 0.017。本文测量的一切都关乎状态**住在哪里**，而非它能记得什么。我们报告一次可审计的受控测量，而不是一个更好的方法。

**关键词：** 对话记忆、上下文压缩、上下文蒸馏、KV cache、参数化记忆、LLM agent

## 1 引言：缺的是载体，不是时间尺度

### 序：它们只是交接，并不记得

一个 agent 走完一段很长的会话，窗口满了，历史被压缩：几百个 token 留下来，其余丢弃。越过边界的不是 agent 学到的东西，而是它说过的话的摘要——像把工作交接给一个陌生人，而且每到一个边界就重复一次。

人类不是这样：睡眠把经验固化进之后要使用它的同一份基质（substrate）。在 LLM 的快权重——即 KV cache——与其冻结权重之间，并不存在这样一层基质。沿着这个思路，我们提出**中速权重**（mid-speed weights），并把方法称为 **AVCP**（AdVance ComPact）。本文要问的是：这个中间层能否在压缩边界处被写入，以及它的代价是什么。

### 1.1 一个具体的断裂点

agent 系统里的会话历史持续增长。为了让上下文窗口可以维持，系统最终会**压缩**（compact）：把较早的历史压成一份摘要，原始文本丢弃。这个操作是有损的，而对摘要来说，损失是不可核验的——没人知道丢了什么。保留指向原始历史的指针的台账（ledger）能让它变得可核查，代价是按使用次数付费（§7）；那是另一种载体、另一套成本结构，不是对摘要的修补。

被丢掉的通常不是任务事实。我们生产引擎里的压缩指令写的是「**保留精确的文件路径、命令、错误字符串、标识符、数值、函数签名**」。它明确列举了事实类目，却完全没有要求保留语域（register）、句长或判断顺序。一个具体例子：如果用户在会话早期要求不要用敬称，而模型在第 20 万 token 处已经照做，那么压缩后应当存活的不是「用户偏好非正式称呼」这条**规则**——规则很容易写进摘要——而是三百个非正式轮次所造成的**语域连续性**。它不是任务事实，而是贯穿整段对话的一种倾向，并制约之后的每一个回答。

这是关于**现有压缩引擎**的论证，不是本文的结论：文本完全有能力承载这类信息（英文 ``the user dislikes honorifics'' 只有四个词）；只是当前的压缩指令没有要求它。这不是修辞上的担忧，生成式压缩的分析支持这一点——其最低预算等价于通信复杂度下界；而不带旁路台账时，侧约束的保留率只有 17% 的测量也支持这一点。

#### 天花板是容量，而不只是成本

我们用所测量的生产级 harness（dsh）来实例化文本载体；它的压缩最多保留 32k token 的摘要，外加 $0.16W$ 的滑动窗口，在缩小版 40k 预设和 1M 预设中都是如此。这些常数是那个引擎的预设；而它们实例化的东西——一个有上限、按次计费的文本载体——不是。$k$ 个 token 的文本载体最多能装 $O(k)$ 比特。按 3 比特/token——一个数量级锚点，来自印刷英语的熵与语言模型的压缩率，而不是对这些对话记录的香农测度——一百万的窗口大约是 375 KB，压缩后存活的大约是 74 KB。三个限制互不相同，不能混为一谈：模型窗口 $W$（此处最多一百万 token）、摘要上限（最多 32k token）、以及一次压缩后存活的总量——对一百万 token 的预设而言约为 196k token，即 $0.16W$ 加上摘要上限。本文各次实验使用约 1k token 的摘要，比上限低一个数量级，这是对文本载体**有利**的情形。这个天花板不随历史增长而移动：第一百次压缩能带走的并不比第一次多。参数载体同样是常数，但量级不同——5.77M 参数，BF16 下 11 MiB、FP32 下 22 MiB，而三投影设计的预算是 33 MiB——并且它只写一次，此后按每个被处理的 token 以常数成本读取。

作为尺度参照：估计人类一生保留约 125 MB 的学习信息，而一百万 token 的窗口按 3 比特/token 约装 300–375 KB。这两个数字的测法不同，不构成容量等式；要点是量级。人类一生的经验比 LLM 一次能承载的多两个数量级以上，而且与人类记忆不同，LLM 的承载能力**不累积**：第一百次压缩能带走的并不比第一次多。又小又固定——这个组合正是本文关心的瓶颈。

### 1.2 「把窗口做大」在物理上走不通

在 Qwen3.8-27B 级别的配置下（64 层，其中 16 层是全注意力，4 个 KV head × 256 维），KV cache 为

$$2 \times 16 \times 4 \times 256 \times 2\ \text{B} = 64\ \text{KiB/token}.$$

163,840 个 token（$2^{20}$ 窗口的 0.16）的常驻 KV 是 10.0 GiB；80 万 token 约 49 GiB，在 96 GB 的卡上就所剩无几了。（48 个线性注意力层另外携带一个与长度无关的循环状态，FP32 下每条序列约 144 MiB；它对 $n$ 是 $O(1)$，不计入每 token 数字。）稀疏化降低的是常数，不是 $n$。换句话说，扩大窗口是一条按历史长度**线性计费**的路。

#### KV 压缩是一条真实有效的路——只是不回答我们的问题

长上下文之所以变得可用，不是因为窗口变大，而是因为 KV cache 被压缩了：DeepSeek-V4.1-Flash 把全局（驻留 HBM 的）KV cache 降到 **890 字节/token**，约为对应 V4 占用量的 1/4，并通过 FP4 KV 缓存与跨层复用把常驻部分降到约 1/8。在这个密度下，一百万 token 的常驻 KV 约 **0.89 GB**——略低于 1 GB。LLM 确实沿着这条路进入了百万 token 时代。Qwen 系列也在往同一方向推。

这条路是本文的前提，而不是对手：没有它，长会话根本无法部署。但它解决的是一个**常数因子**，而不是**信息在不在**：

1. **压缩不等于覆盖。** 把 KV cache 缩小 4 倍，并不改变模型是否真的在用历史；如果训练分布中根本不存在「给定这段历史，就这样回答」的模式，更宽的窗口也生产不出这种模式。
2. **成本仍然在常数意义下是 $O(n)$。** 按 890 字节/token，一百万 token 仍占 0.89 GB，并且每生成一个 token 都要扫一遍。参数载体是 $O(1)$。
3. **它不是神谕。** KV cache 存的是模型在某个前缀上的激活，而不是那段历史的**正确摘要**。它不说该保留什么、丢弃什么，也不提供可审计的权衡。

#### 长上下文退化是训练侧的问题，不是本文的问题

长上下文退化是有记录的：在递归 KV 的设定下，一个以 8k 上下文训练的检查点，到 128k 时降到 35.2%。其主要成因是训练长度分布与位置泛化，本文不处理这些。我们自己探针的边界也应当明说：在 32 个不相关问题上，我们没有检测到全上下文教师出现退化（§6.1）。这是一致的而非矛盾的——那些问题并不需要远端上下文，而我们的比较是教师对 `R`，不是短上下文训练的模型对长上下文模型。

因此我们把 KV 压缩当作一个已经解决的工程前提，把问题放在它之上：**一旦窗口不再是瓶颈，历史应当以什么形式被承载？**

### 1.3 从架构上说，权重只有两种

MiTA 指出：标准注意力等价于一个宽度等于序列长度的两层快权重 MLP，而 FFN 是一个慢权重 MLP：

> 快权重 MLP（注意力，每次前向都重写）+ 慢权重 MLP（FFN，预训练后冻结）。不存在第三种。

这个二分法谈的是**权重**：token 载体既不是快权重也不是慢权重；它是一段挂在旁边的序列，使用时仍必须被展开成快权重。在这个框架内，中间带有两种形态——**文本（现状）或在边界处写入的权重（本文）**——而框架是我们自己划的：某种固定大小的循环状态（有些架构已经在携带它）是我们不覆盖的第三种情形（§6.5）。

### 1.4 本文做了什么

我们把压缩边界当作一个写入点，把一次梯度写入花在一个会话局部的低秩 $\Delta$ 上。三点贡献：

1. **瓶颈识别。** 中间带缺的是载体，不是时间尺度。文本侧有两项成本在累积。**需求**：当必须越过边界而存活的信息随会话增长时，一个固定的载体预算就成为瓶颈——任何文本载体都封顶为「上限个 token 的摘要 + $0.16W$ 的窗口」，与 $K$ 无关。**单价**：把注入长度固定为 $k$ 时，一段被携带的前缀在每个解码位置上增加 $O(k)$ 的注意力计算、在 $m$ 个位置上共 $O(km)$，因为那 $k$ 个 token 就坐在被注意的序列里。固定 adapter 在每个位置上只增加一个常数，不占位置，且只写一次。这是一个**成本论证**，与任何具体模型无关。
2. **可审计的写入协议。** 三条不变量——载体不同、非载体逐字节相同、$\Delta=0$ 时逐位相同——把「参数 vs 文本」变成「各自花多少、占多少」的比较，在匹配 token 下进行，而不是一场刷榜竞赛。
3. **可测量的交叉点。** 我们把「参数能否取代文本」重述为**测量参数载体反超文本载体时的压缩比 $r^\ast$**，而不是争论谁赢。

#### 本文确立了什幺，没有确立什么

序章是论点，不是结果。本文报告的是对它的一次受控测量：会话局部的参数载体究竟能否在压缩边界处被写入、代价是多少、以及它在哪里输给文本。本文**不**主张中速权重能承载一生的经验，也不主张任何特定的容量可达。

#### 实例化与预算

中速权重的设计预算是 33 MiB（FP32 下 66 MiB）：在 rank 64 下，同四层的三个 FFN 投影要花掉我们所交付载体的 3 倍，即 17,301,504 个参数。本版本只在第 60–63 层的 `down_proj` 上挂一个低秩加性更新：5,767,168 个参数，BF16 下 11 MiB、FP32 下 22 MiB。这是最可审计的载体；更大的那个数字是设计目标，不是结果。

## 2 背景与预备知识

### 2.1 四条判据

一项工作只有在以下四条全部成立时才与我们问的是同一个问题，其中第四条以第一条为条件：

**(A) 写入点**：写入是否发生在历史被销毁的那一刻？

**(B) 载体**：推理时记忆是否驻留在参数中，而不是仍以 token、软 token 或 KV 的形式出现在上下文里？训练动过参数本身并不满足 (B)。

**(C) 监督**：学生是否从教师的**输出分布**学习，而不是从任务标签、或先从文本写出来的目标学习？任何在分布上训练的方法都算过关，无论怎么采样。

**($A'$) 生命周期，仅在 (A) 成立时才定义**：产物是否是会话局部的、在 $\Delta=0$ 时可逐位回退、且可丢弃？(A) 不成立时这个问题不存在，我们写「n/a」。

注意 (C) **不是**新颖性的来源：上下文蒸馏从一开始就是这个形式（§2.2）。(A) 和 (C) 各自都很常见：边界触发的文本压缩满足 (A) 而不写参数，文档级编译器满足 (C) 而不在边界处写。无论单独还是与 (B) 合起来，这两列都不稀缺。稀缺的是这个合取。

满足四条中的两三条是常见且合理的情形——每个系统都是为自身设定所提出的约束而设计的，这些判据并不是质量阶梯。

### 2.2 与后训练、上下文蒸馏的关系

最明显的反驳是：*这难道不只是对一个已经学到东西的模型做蒸馏式后训练？***是的，监督项恰恰就是那个。** 上下文蒸馏的标准形式——带上下文的教师、不带上下文的学生、KL 监督——在结构上与我们的目标完全相同，Doc-to-LoRA 的 Eq. 2/4 字面上就是它。我们不主张这是新颖的。区别有四条：

1. **教师一侧不发生任何训练。** 教师不是「一个学过的模型」，而是**同一份冻结权重加一个长 20k token 的前缀**。因此它是原始材料，可以在每个会话上以零训练成本重新导出。
2. **对产物的默认动作相反。** 后训练的产物被期待是一次**永久改进**，其验收问的是「把它删掉会不会变差？」。我们的产物被期待**被删除**，其验收问的是「把它删掉是否恢复逐位相同？」
3. **基线不同。** 后训练与「少训或不训」相比；我们与**在一串 token 预算上扫描的真实摘要、且 adapter 配置固定**相比。问题不是蒸馏是否有效，而是给定预算该花在参数上还是 token 上。
4. **数据预示不同的后续。** 如果这是后训练，下一步就是更多数据和更大容量。我们测得容量放大 4 倍在这段历史上只买到 8 个百分点。我们**不**由此得出训练预算无关：在我们扫描的范围（每个探针 $\le 16$ 遍）内，$64\to256$ 步的增量区间跨零，但这个范围太窄，分不开两种预算；§6.2 报告了一个预算占主导的饱和区间。

一句话：**后训练把一种能力写进模型；我们写的是它的历史。前者必须泛化，后者必须可删除。** 这里还有一个有意味的反转：我们测到的「泛化不足」——方向性的跨历史迁移、在表面扰动下收益消失——在后训练框架下是缺陷，在载体框架下是**证据**。一个能跨历史泛化的 $\Delta$ 会是一个通用微调，而那恰恰是失败，因为它不再绑定于这段历史。

### 2.3 为什么监督信号不来自自生成数据

我们的训练材料不是凭空生成的：$H$ 的主体是外部输入（用户消息、工具返回、文件内容、命令输出）。这不是风格选择。对自生成经验做多轮内化，被报告为**能力渐进坍塌**而非复利增长；在递归生成数据上训练会丢失分布尾部，则是更早的、众所周知的结果。因此监督必须锚定在外部事实上：教师的 $A$ 是外部材料，$\Delta$ 拟合的是它所诱导的分布。

### 2.4 量级锚点（不可互换）

下面这些数字常被并排放置，但它们的测法不同；我们只用它们传达数量级，它们不构成任何容量等式：人类长期记忆约 $10^{9}$ 比特；印刷英语熵 0.6–1.3 比特/字符；大模型可把 enwik9 压到原大小的个位数百分比；人类基因组约 $3\times10^{9}$ 碱基对；人脑约 $8.61\times10^{10}$ 个神经元、$10^{14}$ 个突触。

## 3 方法：在压缩边界处写入

### 3.1 设定与不变量

设 $p_\theta$ 为冻结基座模型，$E$ 为系统消息与工具定义，$q$ 为当前请求。会话历史 $H$ 在压缩边界处被切成一个**块** $A$（将被移除）与一个**尾段** $R$（保留）。压缩引擎为 $\mathcal{K}$，其摘要 $S=\mathcal{K}(H)$ 满足 $|S|\le\mathrm{cap}$。

本文比较的五个实验臂在 §4.3 定义；此处只固定记号。

裸符号 $R$ 永远指被保留的尾段；无记忆臂永远带标签，`R` $=E{+}R{+}q$。下文每个 $\mathrm{KL}(\cdot\|\cdot)$ 都是模型状态之间的，从不是状态与 token 序列之间的。

$\Delta$ 是 FFN 第 60–63 层 `down_proj` 上一组逐层加性更新的**集合**，$\Delta\triangleq\{\Delta_l\}_{l\in\{60,\dots,63\}}$，其中 $\Delta_l=B_lA_l$，rank 64，scale 1，$A_l/B_l$ 为 FP32 且初始化时 $B_l{=}0$；实际装载的层是 $W_l' = W_l + \Delta_l$，而 $\Delta$ 永远不会作为一个求和后的单矩阵出现，因为各因子作用于不同的隐层。因此在 $\Delta=0$ 时，$p_{\theta+\Delta}$ 与 $p_\theta$ 逐位相同。

三条不变量支撑这个比较；任何一条被破坏，配对差值就无法归因。

- **I1 载体不同，非载体相同。** $E$、工具、$q$ 以及任何非载体指令在所有臂之间逐字节相同（包括 `T`）；只有预注册的载体发生变化。
- **I2 共享的载体组件固定。** $S$ 在各摘要臂之间逐字节相同；边界、$R$、$q$ 与解码预算相同。`SD`−`SR` 只改变 $\Delta$。
- **I3 生命周期。** 基座模型全程冻结；$\Delta$ 是会话局部的、单独存储、永不合并、会话结束时清除。

### 3.2 在边界处写入

选择压缩边界有三个理由：(i) 这是历史即将消失的唯一时刻，因此写入的内容与被丢弃的内容一一对应；(ii) 全上下文教师 $E{+}A{+}R{+}q$ 可用，因此它的分布可以在不增加数据成本的情况下采集；(iii) 这是会话的自然分段，使 $\Delta$ 的生命周期有了明确定义。

这个生命周期源于写入点本身，而不是附加在它之上。$\Delta$ 是会话局部的、单独存储、永不合并进基座模型；它在会话结束时被清除，因此不存在跨会话污染，也没有需要清理的「残留」。

### 3.3 载体

载体是对 $l\in\{60,61,62,63\}$ 的 `down_proj` 施加的逐层加性低秩项 $\Delta=B_lA_l$。形式不影响原理，只影响移除成本与反向深度：一个未合并的、5,767,168 参数的低秩 $\Delta$（BF16 下 11 MiB，FP32 下 22 MiB）可以被绕过，且从不触碰基座权重，这使它成为最可审计的选项。

### 3.4 训练目标

对每个训练探针 $q_i$，我们采集教师在 $E{+}A{+}R{+}q_i$ 下的完整输出分布，并在答案位置上最小化全词表前向 KL。记 $c_i^t = E{+}A{+}R{+}q_i{+}y_{i,<t}$ 为教师上下文，$s_i^t = E{+}R{+}q_i{+}y_{i,<t}$ 为学生上下文，

$$\mathcal{L}(\Delta) = \frac{1}{|\mathcal{Q}|}\sum_{i}\frac{1}{|P_i|}\sum_{t\in P_i}\mathrm{KL}\!\left( p_\theta(\cdot\mid c_i^t) \,\middle\|\, p_{\theta+\Delta}(\cdot\mid s_i^t) \right)$$

其中 $P_i$ 是监督位置集合，$y_i$ 是教师答案。我们恰好跑 64 步 AdamW，学习率 $3\times10^{-4}$，并且从不按评测结果挑选检查点。

我们**不在训练位置或训练样本上做任何选择**：所有答案位置都被监督，16 个探针均匀抽取。选择性蒸馏把这一维分解为位置/类别/样本三个轴，并报告由学生熵引导的位置选择（前 20%）在准确率与困惑度上都优于全位置监督；按师生分歧选择样本是相关的一条线。两者都预设了一个值得自适应信任的教师，而这里教师是**经验参照**而非神谕。因此我们保留均匀监督作为基线，并把这个轴列为未扫描（§8）。探针集本身是个占位符：16 个均匀抽取的探针、没有任何覆盖判据，并不是对一段历史的设计采样，整个协议继承了这个弱点（§6.4）。

### 3.5 成本模型

表 1 给出各载体在写入侧与使用侧的成本：文本载体在使用侧付费，$\Delta$ 在写入侧付一次，此后每个 token 付一个常数。

**表 1 四种载体的成本形态**

| 载体 | 写入 | 每次使用 |
|---|---|---|
| 全量/窗口 $A{+}R$ | 无（已付） | $n$ 个 token，KV $\propto n$ |
| 摘要 $S$ | 一次全 $H$ 调用 | $\le$cap 前缀，占用窗口 |
| 台账 | 一次抽取 | $k$ 条注入条目 |
| $\Delta$ | 一次训练 | $O(1)$ 额外矩阵乘，不占窗口 |

因此本文唯一的成本论证是：

> 在缓存稠密注意力与固定模型维度下，一段 $k$ 个 token 的被携带前缀，在每个解码 token 上增加 $O(k)$ 的注意力计算，在 $m$ 个解码 token 上共 $O(km)$。一个固定的未合并 adapter 对每个被处理的 token 增加一个常数计算量，且不占任何上下文位置。对固定的 adapter 配置，其存储与每 token 计算量因此都不随历史长度增长，也不增加任何文本前缀。我们不测量共同单位下的成本比较，也不测量随历史长度变化的等保真度缩放：我们是在固定 $|H|$ 下改变文本预算，因此「adapter 容量随历史长度变化」的曲线在本文中未测。

不做、也不隐含任何归一化：两侧不在同一个单位下计成本。被固定的是监督输入（同一边界、$R$、$q$ 与解码预算）；被扫描的是文本载体的预算。主张只是：$\Delta$ 的成本不随这个扫描的收窄而移动——而不是两种载体的成本相同。

## 4 实验设计

### 4.1 研究问题

- **RQ1 保真度。** 在压缩边界处写入的会话局部 $\Delta$，是否缩小了边界后模型与全上下文教师之间的散度？在每段历史上缩小多少？（§5.1，表 4、表 5）
- **RQ2 位置。** 参数载体在多大的摘要预算处反超文本载体？这个位置在不同历史之间是否稳定？（§5.2，表 6、表 7，图 1）
- **RQ3 代价。** 写入对不需要历史的问题做了什么、这份代价能否被训练掉、还有什么未测？（§5.3，表 8；缺口列在 §8）

三个问题与 §5.1–§5.3、以及 §1.4 的三点贡献一一对应。

**表 2 设计空间：七个旋钮、它们的类型，以及本文各推到哪里**

| 旋钮 | 类型，以及本文的做法 |
|---|---|
| 压缩比 $r=|H|/|S_{\text{body}}|$ | 连续；H20 上五个预算，每段短历史三个 |

### 4.2 历史与问题

四段历史都是同一个生成器产出的合成 agent 会话，不是录制的真实用户会话。H1–H3 是一个四实体、36 笔交易会话的三个变体，各自序列化约 7.1k token；压缩引擎的摘要正文分别是 1989、1086、1178 token，因此在相同 cap 下 $r$ 各不相同。H20 是一段 19.8k token 的会话，由 12 个实体上的 104 笔结构化交易构成，有两个摘要变体 $S_1$（正文 1002 token）与 $S_2$；§5 的 $r$ 阶梯在这段历史上扫描，不相关问题的代价也在它上面测量。每段历史提供 16 个训练、8 个验证、64 个测试问题，共享冻结的教师目标，另加同样的 32 个不相关问题。由于这些历史在内容上不同、而不是彼此的重复实验，一个在它们之间重复出现的数字并不构成一个样本。

压缩引擎从不看评测问题：摘要只由历史产生。一个感知问题的检索策略可能改变比较结果，我们没有评测过，因此我们报告的交叉点是关于**问题盲（question-blind）压缩**的陈述，而不是关于检索增强压缩的。

### 4.3 实验臂与基线

五个臂只在历史的载体上不同；它们共享的 token（$E$、工具、$q$）在所有臂之间逐字节相同（§3.1）：`T` $= E{+}A{+}R{+}q$ 是全上下文教师，`R` $= E{+}R{+}q$ 是无记忆下界，`SR` $= E{+}\mathrm{frame}(S){+}R{+}q$ 是压缩引擎的输出，`RD` $= E{+}R{+}q{+}\Delta$ 是参数化记忆，`SD` $= E{+}\mathrm{frame}(S){+}R{+}q{+}\Delta$ 是互补臂。

**压缩比。** 扫描的自变量是 $r=|H|/|S_{\text{body}}|$，两项都用冻结分词器测量。$|S_{\text{body}}|$ 不含 frame 与摘要模板头，且我们永远报告**实际**长度而不是 cap；对 20k token 的历史 $r\approx20$，精确值按每次运行记录。

### 4.4 评价指标

下文每个数字都来自表 3 所列三个量之一。第一个是保真度指标（教师 vs 臂）；第二个在没有教师参与的情况下测量 $\Delta$ 自身的漂移；第三个读的是文本而不是分布。三者从不合并，因为小的漂移不等于保真，似然也不是分布：前两个比较的是 248,320 维分布，第三个比较的是每个位置上的单个 token。

**表 3 三个指标族**

| 量 | 对象 vs 参照 | 用途 |
|---|---|---|
| $\mathrm{KL}(T\|X)$ | 一个模型状态 vs 另一个模型的全词表分布 | 保真度（主指标） |
| $\mathrm{KL}(X_{\text{off}}\|X_{\text{on}})$ | 一个模型状态 vs 关掉 $\Delta$ 的它自身 | $\Delta$ 自身漂移 |
| NLL / PPL | 一个模型状态 vs 作为点质量的文本 | 摘要通道、gold 似然 |

**位置集与加权。** 相关问题沿**同一条冻结教师路径**取答案位置，所有臂共享同一批目标 token id。32 个不相关问题共享一个固定 gold 前缀，总共贡献 50 个计分位置，而不是每个 50 个。计分时先在问题内对位置取平均，再对问题等权；我们报告实际位置数、截断与覆盖情况。

### 4.5 不确定性与数值路径

**不确定性。** 我们使用 10,000 次以整道题为单位的配对自助重采样（seed 20261025），并且只比较**同一**重采样内的配对差值，从不比较两个独立的区间。token 不被当作独立样本；摘要通道只有三个目标，我们刻意不构造 token 级区间。每段历史最多四个生成簇，我们报告整簇重采样的区间，仅作方向性信息。不做多重比较校正；区间以固定历史、adapter 与问题池为条件。

**数值路径。** 主测量使用 `use_cache=False` 的冷启动通过；共享前缀缓存作为敏感性分析报告（冷→缓存的平均 KL 量级为 $5\times10^{-4}$）。我们使用全词表 log-softmax（248,320），不做截断或 top-$k$，以 FP32 计算。每次运行都保存原始张量与 SHA 摘要；负值从不截断。

### 4.6 判定规则

1. 报告带区间的配对差值；不要比较两个点估计的区间是否重叠。
2. 比率型量（如相对降幅）只在分母大到足以支撑时才报告；否则只报绝对差值。
3. 分布距离改善不蕴含任务准确率或语义保持。
4. 在某一个配置下打平，不能证明历史效应无法被参数化。

### 4.7 实现细节

基座模型 Qwen3.8-27B BF16，修订 `1d4bf0f2`（完整哈希见数据可用性声明），单张 RTX PRO 6000（97,887 MiB）。每段历史 16 训练 / 8 验证 / 64 测试问题，共享同一批冻结教师目标；64 步 AdamW，学习率 $3\times10^{-4}$；自助重采样种子 20261025。所有输入、张量与统计脚本以 SHA 冻结（除了一次有记录的事后交叉检验更正）；失败与截断均予保留。我们没有对 batch size、墙钟时间或峰值显存做插桩，因此 §3.5 的成本主张是解析性的而非实测的。

### 4.8 设计空间

表 2 铺开了本文所处的空间。三个旋钮被扫描，两个固定，一个未分离，还有一个根本没有参数化。探针那一行才是有意思的：探针集是在选择「向这段历史问哪些问题、监督哪些位置」，而在我们的协议里这两侧都没有定义好的维度——我们均匀取了 16 个问题，并监督了每一个答案位置。这个选择没有一处是中性的（§6.4），这也正是 §6.5 把探针选择放在第一位的原因：载体之间的每一次比较都以某个探针集为条件，而一个有一半轴都没定义的空间是无法枚举的。

### 5.2 RQ2：压缩比交叉点

由于 $\Delta$ 不读 $S$，`RD` 臂是一条约在 0.2553 的水平线，而 $\mathrm{KL}(T\|\text{SR})$ 随摘要被压缩而**上升**——从 $r=19.8$ 的 0.0946 升到 $r=309.8$ 的 0.3286（表 7、图 1）。因此这个测量是一个**位置**问题，不是假设检验；而在两个相邻预算处我们观测到符号翻转：在 $r=77.5$ 摘要仍显著优于参数载体（配对 $\Delta\mathrm{KL}=-0.0436$，CI $[-0.0897,-0.0010]$），而在 $r=154.9$ 符号已翻（$+0.0569$，CI $[+0.0137,+0.1037]$）。我们报告夹逼区间 $r^\ast\in[77.5,154.9]$，不对单一值做插值；这是采样预算的一个范围，不是交叉点的置信区间。等价地说，在这段历史与这个摘要策略下，交叉点位于 128–256 个摘要 token 之间。

表 6 在三段小历史上重复了扫描，使用同样的臂与同样的冻结教师路径。三者都发生了次序反转，但预算不同。H1 给出最干净的夹逼：50 token 时参数载体更好（配对 $+0.0650$，CI $[+0.0296,+0.1075]$），200 token 时摘要更好（$-0.0568$，CI $[-0.1041,-0.0146]$），两个区间都不含零。H2 在 10 与 50 token 之间变号，但只有 50 token 那一端不含零（$-0.0352$，CI $[-0.0624,-0.0108]$；10 token 时 $+0.0272$，CI $[-0.0097,+0.0663]$）。H3 只在接近 200 token 时才追平固定载体，而那里两者已不可区分（$-0.0012$，CI $[-0.0193,+0.0169]$）。10 token 的摘要不携带任何可辨识的历史：三者都退化成章节标题，因此它们是一个合法的预算点而非可用载体，我们将其保留为扫描的低端。

### 5.3 RQ3：代价

一个把分布拟合进权重的载体，会扰动这些权重所做的一切，包括从不需要历史的问题。表 8 在 32 个不相关问题上报告三个量，因为它们回答三个不同的反驳：分布漂移（这些问题上的行为移动了多远）、gold-NLL 效应（这个移动是否让答案变差）、以及贪心比较（它是否改变了任何一个答案）。

漂移的点估计比同样问题上任一文本载体都大（0.02587，两个摘要分别是 0.01663 与 0.01597），而 gold-NLL 效应为正且区间不含零（$+0.0349$，$[+0.0105,+0.0756]$）。漂移差值的配对区间跨零，因此我们报告这个次序而不主张它。贪心路径在每一个臂里都没变——32 题中 31 题正确，且从未出现从对到错的翻转——因此我们测到的漂移并没有改变答案：gold 似然动了，而实测的贪心结果没动。这也意味着这个行为学检验在此几乎没有余量，我们不把它的稳定读作无害的证据。

**代价能否被训练掉？** 只被测量的代价会让论证悬空，所以我们跑了最直接的补救。排练（rehearsal）把原始写入与在跑题问题上的更新交错：每四次历史更新后跟一次排练更新，于是 adapter 收到 64 次历史加 16 次排练更新而不是 64 次，排练损失乘以 $\lambda$。两个变体都保持 H20、种子、rank 与层集合不变；$\lambda{=}0.5$ 是把损失权重减半，不是把更新次数减半，也不等同于把优化器步长减半。

两个变体朝同一方向移动。$\lambda{=}1$ 时 NLL 效应变为 $-0.0016$，其区间跨零：效应已无法与「没有」区分，尽管我们先前固定的门槛——上界在零或以下——仍未达到。相关侧付出了大约一个点（配对差 $-0.86$ pp $[-2.18,+0.69]$）。把损失权重减半在两列上都更差，因此这个权衡不会因为缩小该项而改善。两个变体都没有同时满足两个预注册条件——相关侧的配对下界 $-2$ pp 的非劣性界，以及跑题 NLL 的上界在零或以下——我们也不在封存测试集上继续做 $\lambda$ 搜索。

**三行分开了什么。** 一次权重更新造成的效应，也可以被另一次权重更新减弱，因此排练的胜利本身并不说明代价来自哪里。它说明的是这个效应不是惰性的：十分之九的漂移与 NLL 效应中可检测的那部分都消失了，代价在相关侧。在这个设定内——一段历史、一个种子、两个排练权重——实测的副作用因此对训练目标敏感，我们就这么报告；它并没有为参数载体确定一个内在下界。

**要点。** 写入在从不需要历史的问题上付出漂移，比两个摘要的点估计都大，而排练以约一个点的保真度为代价去掉了其中十分之九。实测副作用对训练目标敏感；两个预注册的成功条件都没有达到。

## 6 讨论

### 6.1 对三种替代解释的检查

1. **「全上下文教师已经退化。」** 在 32 个不相关问题的 50 个 gold 位置上，$\mathrm{KL}(T\|\text{R0})=0.054753$，但教师相对 `R0` 的 gold NLL 差为 $+0.009531$，区间 $[-0.008318, 0.026700]$，跨零。因此我们没有在这些问题上检测到教师的 gold NLL 存在差异：该区间与「小幅改善」和「小幅退化」都相容。这与已记录的长上下文退化并不矛盾：我们的探针使用不需要远端上下文的问题，而且它比较的是教师对 `R0`，不是一个短上下文训练的模型对一个长上下文模型。
2. **「摘要通道的负结果只是缺一个格式模板。」** 给四个臂套上同一个八节标题模板，降低了每一个核心交叉熵，但基本没有改变臂之间已观测到的排序。模板移动的是地板而不是排序，因此它无法解释摘要通道上的负结果。
3. **「容量无关。」** 把 rank 从 64 降到 16，使 H3 上 `R0`→`RD` 的相对降幅从 27.90% 降到 20.03%，差值为 $+7.87$ pp，区间 $[5.55, 10.66]$ 不含零。两个数都来自 H3 上的容量扫描；它的 rank-64 参照是一次冻结的早期拟合，所以这里读到 27.90%，而表 4 里是 27.95%。因此，容量在这个配置下有可测的效应，但 4 倍容量只买到约 8 个点，该效应在 `SR`→`SRD` 上不可检测，而在两个 rank、一个采样条件下，我们无法把它与其他未扫描的轴排序。

### 6.2 另一规模上的复制

在这个规模上做一次饱和写入很贵——2,304 步，即对 36 个训练探针做 64 遍，另加每段历史一次完整教师通过——放不进本版本的窗口。因此我们在 Qwen3.5-9B 上、用它自己的历史、问题池与摘要方法，把饱和区间跑了一次。协议是独立的，**它的数字不得与 §5 的数字相减或合并**；它是一个复制探针，不是第二个实验。它展示的是形状，不是幅度：

**表 9 9B 伴随运行补充了什么**

| 观察 | 9B 伴随运行 |
|---|---|
| 交叉点 | 存在；插值在 540–650 个摘要 token 处 |
| 写入预算 | top-1 0.220→0.497，KL 0.7230→0.7508，4 到 64 遍 |
| 探针覆盖 | 一个留出的单字段集合停在 0.31；覆盖它后升到 0.84 |
| 跑题漂移 | 饱和处未测 |

有三件事成立。反转在那里也存在，token 数是我们自己的两到八倍，所以被复制的是「交叉点存在」，而不是它**在哪儿**。写入预算在饱和之前起作用，而两个指标是否同向移动取决于比较的是哪一对预算：在 40 题评测上，4 遍到 64 遍把值位置 top-1 从 0.220 提到 0.497，而 KL 略变差（0.7230 到 0.7508）；而 16 遍到 64 遍两者都改善（0.288 到 0.497，KL 0.7661 到 0.7508）。因此我们把两个指标并排报告，绝不把一个读成另一个。而在饱和处，给定位置上的数字可以从 adapter 自身的贡献解码出来，所以「拟合了一个分布」是**写了多少**的问题，不是载体的属性（§6.4）。这次运行不给我们的是这个模型上的一个数字：27B 的饱和 adapter 不存在，在它存在之前我们无法说载体是否补上了与摘要之间的差距（§5.3）。细节——解码探针、未扫描的轴、确切的协议——在附录 A。

**对「探针问什么」的一次干预。** 伴随实验测的是与上一条不同的轴。用 56 个训练探针时，adapter 在八个留出的单字段问题上值位置 top-1 为 0.3125，尽管那些实体及其值已经在三字段训练答案中出现过。加入 24 个措辞不同的单字段探针后，同一分数升到 0.84375。那次干预同时改变了训练分布**和**更新总数（3,584 到 5,120），因此它表明的是对探针集「实体—答案格式」覆盖的敏感性；它既没有分离出事实覆盖的极限，也没有分离出容量极限。措辞位于比较的另一侧，但属于另一次运行：在一个 2,304 步的 adapter 上，答案形状固定的改述三字段问题上，值位置 top-1 为 0.969。这些测试在我们试过的措辞与答案格式变化下显示出不同的敏感性；它们没有分离出一个普遍的「措辞 vs 格式」区分，而且三个数字来自三个不同的检查点。

我们认真对待两个后果。第一，交叉点随探针集移动：准确率口径的点估计在 2,304 步的 adapter 上是 6.76（就是得 0.969 的那个），在 5,120 步的 covered adapter 上是 4.20（就是得 0.84375 的那个），在那个曲线与那个指标上是 1.61 倍，不是容量比。这与上面 3,584 到 5,120 步的干预是**不同的一对**——探针构成与优化曝光同时变化——因此它定位的是一种敏感性，而不是纯粹的探针效应。第二，我们自己在 §5.2 的交叉点以它自己那个稀疏探针集为条件；在 27B 上做等价干预的方向与幅度均未测。

### 6.3 一个我们尚未检验的推论

一次会话局部的写入会留下一条可审计、可重放的记录，记载这段历史对模型的分布做了什么。跨许多会话累积起来，这样的记录正是一个持续学习过程所需的原材料，用以覆盖今天只能靠长上下文训练获得的行为。我们的 $\Delta$ 本身并不累积——它是会话局部的、会被丢弃——因此，被报告为多轮内化风险的那件事在此没有作用机制。

### 6.4 局限

1. **分布拟合不是内容断言。** $\Delta$ 拟合的是教师的输出分布，§5 里每个数字都是分布距离。伴随实验显示了对训练曝光与「实体—答案格式」覆盖的敏感性，但它的干预同时改变探针构成与更新次数，所以它没有分离两者的作用，我们不把差异单独归因于覆盖（§6.2）。在 27B 上，我们测的是分布保真度，不是独立的表格重建或事实准确率。
2. **不主张任务准确率。** 更小的分布距离不蕴含任务能力，我们不主张在任何基准上准确率提升。
3. **探针集是最弱的一环，而我们对如何选择它没有方法。** 我们均匀抽 16 个探针，对历史内容的覆盖没有判据、没有抽样框、对其数量与分布也没有敏感性分析；一个太小、太集中、或只取自历史某一部分的探针集，看起来会与载体的极限一模一样，而我们现在分不开这两者（§8）。
4. **在不相关问题上有真实代价。** 把一个分布写进权重，会扰动那些不需要历史的问题：在 H20 上漂移为 0.025874，而加一个摘要是 0.016631/0.015966。排练把这漂移降了一个数量级，代价是少量保真度，但不是免费的（§5.3）。
5. **载体能回答什么，取决于探针问了什么。** 在这段历史上，正文 1002 token 的摘要比单独的 $\Delta$ 更接近教师（0.0946 对 0.2553）。在伴随实验里，八个留出的单字段问题在每种答案形状都被训练过后得 0.3125，加入单字段探针后得 0.84375——那次干预也改变了更新次数，所以它给出了这个读数随探针集移动的幅度，却没有分离出是哪个因素在动（§6.2）。当历史在 schema 复杂度上增长时，同样的事成立到什么程度，是开放的。
6. **写入需要块还活着。** 教师是 $E{+}A{+}R{+}q$，所以写入必须发生在 $A$ 被销毁之前；一个已经丢弃了块的引擎，不重放就无法事后补写。
7. **每个会话一次梯度写入。** 边界处的 64 步 AdamW 是每会话的成本；一个对历史做超网络的方法会把它摊销掉（Doc-to-LoRA 正是如此），但那是另一种机制，我们没有实现。
8. **会话局部且不累积。** $\Delta$ 在会话结束时被丢弃，因此没有任何东西跨会话留存；一个真会累积的过程将要面对我们引用的坍塌风险。

### 6.5 未来工作

在三件事挡在这些数字与方法之间，按顺序。

**选择探针。** 这是那个卡点，伴随运行说明了原因：在我们试过的各种干预中，「探针集问什么」比我们变动过的任何东西都更能移动读数，所以探针集是仪器的一部分，而不是一个中性的样本。我们的 16 个探针均匀抽取、覆盖很少的格子、没有任何判据来验证，这使得「载体失败」与「探针集从没问到点子上」无从区分（§6.4）。伴随实验也显示了这份收益有多大：多 24 个单字段探针、七分钟的教师与训练时间，把一个留出集合从 0.3125 提到 0.84375（§6.2）——那次干预也改变了更新次数，所以收益的**大小**是确立的，它的**归因**不是。需要的是一套对历史 (实体, 字段) 式网格的覆盖模型、一个明示的抽样框、以及在探针数量与分布上的敏感性分析——并且，因为覆盖会改变交叉点，这个文献里的每一个 $r^\ast$ 都应当连同产生它的探针集一起报告。

**历史多样性。** 我们的四段历史是同一个生成器的变体：同样的交易文法、同样类型的问题、H1–H3 中四个实体对 H20 中十二个实体。交叉点位置在四段上都测了，排练的权衡只在 H20 上测了，而我们不知道这两者中任何一个能否在结构不同的历史上存活——一个代码库、一条日志流、一段没有类型化字段的长对话。相关的变动是结构性的，不只是更长。

**模型泛化。** 我们在目标规模上有一个基座模型，在另一个协议下、较小规模上有一个复制（§6.2）。这足以显示形状不是某个检查点的产物，不足以说另一个模型的交叉点在哪里。下一次运行应当是在同规模的第二个模型上跑同一套五臂协议，而不是在这个模型上再加一个臂。

### 7.1 把上下文编译进参数：有界文档区间

Doc-to-LoRA 用一个超网络在一次前向里把上下文编译成 LoRA adapter，把梯度步摊销掉；RPMem 换用更强的超网络骨干（会话 → 潜编码 → LoRA）；DPPM 走「证据 + 增量」双路；Doc-to-Atom 用带路由的原子级 micro-LoRA；Memory Depth 用惊奇度与效价来门控 LoRA 写入。它们的写入点在会话、任务、文档或若干轮的末尾；我们的写入点在历史被销毁的那一刻。这些是不同的触发条件，因此下面的比较不是同一问题上的较量。

这个家族已经在**没有原始上下文**的情况下做推理评测：Doc-to-LoRA 的检索评测只把查询给目标模型，文档由 adapter 承载。所以「文本没了、只剩参数」不是本文与它们的区别。区别在触发点与测量：它们的写入点是任务、文档或会话边界，我们是引擎销毁块的那一刻；并且我们在扫描的 token 预算上，把载体与一个真实的摘要生成策略相比。

我们的写入点由上下文的濒死触发：在 `RD` 臂里，$A$ 已经被移除，$\Delta$ 是它**唯一**的载体。问题变成「参数能否取代已经不存在的文本？」因此对照臂、成本结构与失效模式全都不同。

这个家族还有一项被报告过的代价：当上下文与预训练先验冲突时，Doc-to-LoRA 式方法会塌到 46.4%。我们没有测试这类冲突，并将其记为未覆盖，而不是记为「已经规避的风险」。

### 7.2 在 episode 边界上的 TMEM：最近的邻居

TMEM——*Scaling Self-Evolving Agents via Parametric Memory*——是最近的邻居：episode 边界触发、在线 LoRA、$B{=}0$ 时的真恒等、写入后清空上下文。差别只有一处：**它的监督先经过一次 JSON-QA 抽取**。因此 $\Delta$ 学到的是抽取器能问的东西——从未被问及的事实、无法被措辞的倾向、跨事件的一致性，都不进入监督通道。那一步也换来了东西：文本形式的监督是可检视、可归因、可拒绝的。所以准确的说法不是它「多了一步」，而是两套方案**在监督通道上不同**：一个由抽取器中介，另一个是答案位置上的直接分布。直接通道事实上是否承载了更多可用信息，是一个我们未测的假设——我们自己的监督本身就受探针集限制（§6.4），所以「更大带宽」需要它自己的实验。

### 7.3 把历史留在 token 一侧

另一条线把压缩后的历史留在 token/KV 一侧：Cartridges 离线把上下文编译成紧凑 KV，而独立训练的 cartridges 朴素混合会塌成随机；REMORY 使用有界软记忆 token；LOHA/ACD 把旧观测压成软 token（SWE-bench 12.1/21.8 对未压缩的 14.5/27.5）；它的锚定蒸馏是一次分布匹配，与我们相同，但两者写的东西不同：ACD 为一个仍留在序列里的载体训练一个读者，而这里的蒸馏写的是载体本身，历史离开序列。REMORY 把这一点说得更锐利：它就在压缩边界上做蒸馏，却仍然写软 token。两者在成本上都不是我们的替代品：它们都把压缩后的历史留在序列里，因此占用窗口位置，并支付与注入 token 数成正比的注意力计算（§1.2）。Still 用逐层 Perceiver 递归压缩 KV；RestoreKV 用 LoRA 恢复被逐出的 KV。这些方法是有效的，也是在窗口足够宽的那个区间里的自然选择。它们的成本项是 token 或 KV，所以当窗口本身成为约束时，缩小的是那个常数——KV 压缩买到的是余量，不是对「仍被携带的位置数」的独立性（§1.2）。

### 7.4 参数对 KV：既有比较说了什么

公平地说，参数在**检索**上并不占优：EVAF 报告事实检索为 0.956–0.973，而参数内化为 0.812–0.904；另有报告称在匹配预算下 KV 比参数高约 10 个点，且参数是唯一表现出灾难性遗忘的臂。我们只主张**成本形状**不同，所以在文本预算必须保持很小的区间里，参数载体还有预算可用，保真度即我们所测的那样。这也是为什么我们必须报告不相关问题上的漂移——一项在既有工作中被确认的代价——并且把它单独列出而不是省略。

## 8 有效性威胁

**构念。** 主指标是分布距离，不是任务准确率：在 32 个不相关问题上贪心准确率为 31/32，没有余量，而相关问题没有独立于教师的 gold，所以**没有确立任何任务层面的效应**。该指标也不说明一个差异是由答案的哪一部分承载的：全词表 KL 是在表层 token 上取的，没有被分解为历史的类型化数值（§4.2）与表达它们的表层形式。分布距离也可能在行为不动的情况下显得令人满意：在 §6.2 的伴随运行里，从 4 遍到 64 遍把值位置 top-1 翻倍（0.220 → 0.497），而 KL 略变差（0.7230 → 0.7508）。两个指标回答不同的问题，所以我们并排报告，绝不把一个读成另一个。

**内部。** (i) 训练集是 16 个探针，由我们均匀抽取，**没有覆盖判据，也没有探针质量度量**；它们的抽样方差未测，所以关于容量与步数的每个结论都以某个规模的一次抽样为条件，我们无法把载体极限与探针极限分开（§6.4）。伴随实验给出了这个窟窿有多大：用按问题措辞的探针覆盖同样的格子，把一个留出格子从 0.31 提到 0.84，所以这里的 16 个探针不是一个中性选择。(ii) 只有四个生成簇；无多重比较校正；区间以固定问题池为条件。(iii) 未扫描的轴：层位置、教师目标长度、探针数量（已扫描：rank 16/64，更新 0/16/64/256，即每个探针最多 16 遍；伴随运行在 9B 上扫到 64 遍，发现预算具有决定性）。表 2 铺开了整个空间以及我们推动了其中哪些。(iv) §3.1 的三条不变量由构造强制、由哈希验证，但我们没有跑一个故意违规的臂，所以无法界定一次违规会吸收掉多少配对差。

**外部。** 四段构造历史、单个 27B 基座模型、单张 GPU；真实会话的熵与噪声结构未被覆盖。

**测了什么、没测什么。** 漂移只在一段历史、一个种子上测过。写入侧未做插桩：我们报告参数、字节与更新次数（§3.5），不报告墙钟、峰值显存或首 token 延迟。而代价是在我们拟合的那个预算上测的，所以它是否随 adapter 饱和而增长是开放的（附录 A 记录了同一个缺口）——这也正是排练权衡会最先破裂的地方。

**运行范围。** 产物很小；研究它不是。一次饱和写入是 2,304 步（36 个探针 64 遍）外加一次覆盖整段历史的教师通过，而每一轮扫描的每一个臂都需要它自己的冷启动通过；围绕状态处理、前缀缓存与逐字节验证的工程成本，比 GPU 小时更贵。因此我们没有完成这项研究：27B 的阶梯停在每个探针 16 遍，饱和区间是从一个 9B 伴随运行而不是从本模型报告的（§6.2），第二个种子、匹配预算的成本比较、更宽的历史集合都没有跑。缺的东西是因为成本而缺，不是因为假设被放弃；我们宁愿这样说，也不愿用无法相互比较的运行把这个空间填满。

## 9 结论

我们问的是：跨压缩边界承载历史的载体能否是参数而不是文本，并且把答案测出来而不是辩出来。我们在边界处把全上下文教师的输出分布写入一个会话局部的、未合并的低秩 $\Delta$，它在被清除时逐位相同。在单个 27B 模型、四段构造历史上，这次写入对仅尾段基线把与教师的散度降低了 25.1/28.0/28.5%，在第四段历史上的降幅为 7.7% 且其区间跨零，在一段历史上于摘要之上再降 17.8%。在一段 20k token 的历史上，文本载体一直更近，直到摘要被压到 128–256 token，比较在那里反转。在三段较短的历史上，采样点估计再次反转次序，预算落在 10 到 200 token 之间，但三者中只有一者被两个区间都不含零的端点夹住，因此我们不报告一个可迁移的交叉点位置。在不需要历史的问题上，$\Delta$ 的代价是 0.026 nats/位置，而加一个摘要是 0.017。本文确立的是：状态可以住在参数里，以及那要花多少；在此处使用的写入预算下，同等长度的摘要仍比单独的 $\Delta$ 更接近教师，所以这个主张是关于状态**住在哪里**，而不是关于取代文本。

## 附录 A 一个 9B 伴随研究

第二项研究在 Qwen3.5-9B 上、单张 22 GiB GPU 上运行，在一张 36 实体的服务表上、用它自己的问题池重复了这次测量。协议是独立的，因此**它的数字不得与 §5 中的数字比较**。它存在的原因是饱和区间在 27B 上放不下：36 个探针上的 2,304 步外加一次覆盖整段历史的教师通过，与我们此处研究的 64 步写入不是同一个量级的成本，而一次 9B 运行是在本版本的预算内看到那个区间的唯一办法。我们报告它，是因为它关系到上文的三项主张；正文中的摘要是 §6.2。

**交叉点。** 在同样两个采样端点之间做 log-$r$ 插值，把交叉点放在按 KL 的 $r^\ast\approx5.5$、按值位置 top-1 的 $\approx6.8$（改述问题上为 5.85），即 540–650 个摘要 token。采样得到的夹逼更宽：它跨越 512 与 1024 token 两个预算，是 §5.2 的 128–256 token 的两到八倍。结果的**形式**复现了；token 数不跨模型迁移。

**写入预算。** 固定其余一切、只改变每个被监督实体的遍数，拟合后 adapter 的「训练措辞」值位置 top-1 从 4 遍的 0.32 移到 64 遍的 1.000，改述问题的 top-1 从 0.20 移到 0.59 后饱和（再花 $2\times$ 的步数：仍是 0.59）。在同一区间里 KL 走错方向：从 4 遍到 64 遍，40 题集合上的 top-1 从 0.220 升到 0.497，而 $\mathrm{KL}(T\|\cdot)$ 上升（变差）0.7230 → 0.7508。我们并排报告两者，不把一个读成另一个；我们也不认为 KL 坏了，因为两者回答不同的问题（一个完整分布对一个 top-1 token），而这个分歧的成因在此未被分解。

**覆盖。** §6.2 背后的两次运行在探针问什么上不同，也在更新次数上不同，所以两者都没有单独分离出覆盖。第一次训练了每种答案形状——36 个三字段、12 个二字段、8 个单字段（字段轮换）探针，3,584 步——并留出八个其他实体上的单字段问题。第二次保留这些形状，并加入 24 个我们自己的措辞的单字段探针，针对那些单字段问题从未被问过的实体（80 个探针，5,120 步）。加上那 24 个探针的成本为 173 秒教师目标、224 秒训练。漂移以及 rank 与层这两个轴只在低预算下扫描过，更大预算下的 27B 运行不存在，所以 §5 的载体在训练更久之后是否补上与摘要的差距，是开放的。

**解码。** 在输出某一位数字的位置上，一个线性分类器从 adapter 对 MLP 输出的贡献中解码下一位数字，在来自 36 个探针的 250 个教师强制数字位置上达到 0.928 的准确率，而同一前向中采集的基座 MLP 特征为 0.472，多数类基线为 0.192。这确立了那些位置上的**条件可解码性**；它不是仅凭 adapter 权重重建那张表。
